# D9 docs 19–22 審閱

審閱者：fable｜日期 2026-09-26｜範圍：`docs/19-檔案與檔案系統.md`、`docs/19b-檔案系統與路徑.md`、`docs/20-錯誤處理與資源管理.md`、`docs/20b-資源管理.md`、`docs/21-數字與位元.md`、`docs/22-原型與方法.md`

## 總評
六篇整體說法多數與 1.41.2 實跑相符，範例輸出格式一致，⚠ 點破誤解的寫法用得好。最大問題是兩處會讓讀者照做就炸的錯誤：`docs/20:22` 的 `(propagate e)` 少了 fiber 參數（arity 錯誤），以及 `docs/19:11` 把 `slurp` 回傳說成 string（實為 buffer，會讓 `=` 比較與 table key 全失敗）。其次是 `file/open` 失敗回 nil、放進 `with` 會把原始錯誤蓋掉這個常見情境完全沒提。最值得先修：`docs/20:22` 的 `propagate` 範例。20 與 20b 的「可跑範例」段重複、20 標題與內容不符，屬結構小問題。

## 發現
- [高][錯誤] `docs/19-檔案與檔案系統.md:11` — `slurp` 回傳的是 **buffer** 不是 string（`(type (slurp "out.txt"))` → `:buffer`，`(= (slurp f) "hello\nmore\n")` → `false`），註解「讀成一個 string」是錯的；而且第 43 行只針對 `file/read` 警告 buffer 陷阱，讀者會以為 `slurp` 是安全的 — 改成「讀成一個 buffer」，並把第 43 行的 ⚠ 擴到 `slurp` — [實測]
- [中][範例] `docs/19-檔案與檔案系統.md:27` — `file/open` 開不到檔**回 nil 不拋錯**（`(file/open "nope.txt" :r)` → `nil`），跟第 14 行強調的「`slurp` 會拋錯」正好相反卻沒講；放進 `with` 後 body 先炸 `file/read` on nil，收尾再炸 `unknown method :close invoked on nil`，原始錯誤被蓋掉 — 加一段 ⚠ 說明並建議 `(assert (file/open ...) "開不到")` 或先 `os/stat` — [實測]
- [低][錯誤] `docs/19b-檔案系統與路徑.md:13` — `os/stat ... :mode` 列出 `:link`，但 `os/stat` 會跟隨 symlink，對 symlink 回的是目標的 `:file`；要看到 `:link` 得用 `os/lstat` — 改成「`:file` / `:directory`；symlink 要 `os/lstat` 才會回 `:link`」 — [實測]
- [低][範例] `docs/19b-檔案系統與路徑.md:29-30` — `os/mkdir` 已存在回 false 有講，但 `os/mkdir "a/b/c"`（父目錄不在）跟 `os/rm` 檔案不在都會**拋錯**（`No such file or directory`），`os/dir` 目錄不在也拋錯；本篇只有 `os/stat` 一個回 nil 的例子，讀者容易以為 `os/*` 都不拋 — 在表格旁補一行「哪些會拋」 — [實測]
- [低][結構] `docs/19-檔案與檔案系統.md:58-77` — Windows 換行陷阱佔全篇近四分之一，且標「實測」但本機是 Linux 無法重現；放在 slurp/spit 基礎之後、`os/stat` 之前打斷主線 — 考慮移到 19b 末尾或縮成一個 ⚠ 加連結 — [疑]
- [低][文風] `docs/19b-檔案系統與路徑.md:5` `:17` `:35` — 連續三處用「——」當停頓，跟 writing.md「別拿破折號製造停頓感」相違 — 改句號或逗號 — [疑]
- [高][錯誤] `docs/20-錯誤處理與資源管理.md:22` — 範例 `([e] ... (propagate e))` 跑不動：`propagate` 至少要兩個參數 `(propagate x fiber)`，實跑報 `<function propagate> expects at least 2 arguments, got 1`；讀者照抄「重新拋出」會直接炸 — catch 改寫成 `([e f] ... (propagate e f))`，並在第 25 行說明第二個參數是 fiber（27 行才介紹 fiber，順序要調） — [實測]
- [中][錯誤] `docs/21-數字與位元.md:56-57` — 說 `(int/s64 9007199254740993)` 會拿到「掉過精度的 double」暗示靜默出錯；實跑是**拋錯** `can not convert number 9.00719925474099e+15 to 64 bit signed integer`（超過 2^53 的 number 拒轉）— 改成「會直接報錯，所以大數一定寫字串」，順帶把這當成好事講 — [實測]
- [低][文風] `docs/20b-資源管理.md:19` — 寫「提早 return」，Janet 沒有 `return`；`examples/errors-raii.janet` 自己的說法是「提早跳出（break）」，兩邊術語不一致 — 統一成「提早 `break` 跳出」 — [實測]
- [低][結構] `docs/20-錯誤處理與資源管理.md:115-122` 與 `docs/20b-資源管理.md:46-54` — 「可跑範例」段落幾乎逐字重複（同一支 `examples/errors-raii.janet`、同一句「那才是它等同 RAII 的地方」）— 20 只留一行連結到 20b — [實測]
- [低][結構] `docs/20-錯誤處理與資源管理.md:64-69` — 標題含「資源管理」但內容全搬到 20b，本篇只剩三行轉介，標題與內容不符 — 標題改「錯誤處理」，或把「三者怎麼選」表移到 20b 收尾 — [疑]
- [低][範例] `docs/20b-資源管理.md:30-36` — `with` 的物件沒有 `:close` 時的實際錯誤（`unknown method :close invoked on <table ...>`）沒有秀出來，只有文字說明；讀者第一次碰到看不懂訊息 — 補一行實跑輸出 — [實測]

- [低][結構] `docs/21-數字與位元.md:121-140` — 「比較與排序」（`sort`/`sorted`/`reverse!` 命名規則）跟數字與位元主題無關，且 `sort` 就地改的說明屬容器篇範圍 — 移到容器／函式篇或刪 — [疑]
