# 05d · 引用自己的另一個本地專案

[← 05c jpm 的 rule 系統](05c-jpm-的-rule-系統.md)｜回到 [05 jpm 與專案結構](05-jpm-與專案.md)

[05](05-jpm-與專案.md) 講的是裝**別人**的套件。要 import 自己在另一個目錄寫的東西，
有兩條路：開發期用相對路徑，穩定了再裝進模組樹。

## ① 相對路徑（開發期建議用這條）

```janet
(import ../../repo/langs/janet-lab/modules/llm-http/init :as llm)
```

三條規則，缺一不可（完整版見 [`../snippets/import-files/main.janet`](../snippets/import-files/main.janet)）：

1. **相對的是「寫這行 import 的那支檔案」**，不是你 `cd` 在哪。同一行複製到別層就錯。
2. **一定要有 `./` 或 `../` 開頭。** 沒前綴的裸名字走系統模組路徑（`(dyn :syspath)`）。
3. **絕對路徑不能用**，開頭的 `/` 會被吃掉。

還有兩個很容易踩的：

- ⚠ **`~` 不是家目錄。** `~` 在 Janet 是 quasiquote，`~/repo/x` 被讀成
  `(quasiquote /repo/x)` 一個 **tuple**，錯誤訊息長成看不懂的
  `could not find module <tuple 0x...>`。
- ⚠ **不要帶 `.janet` 副檔名。** 那是**模組名**不是檔名，Janet 自己會接
  `.janet`／`.jimage`／`.so` 去找。

好處是改了模組立刻生效，不用重裝；壞處是要自己數 `../`。

## ② 裝進模組樹，用裸名字 import

`project.janet` 裡有 `declare-source` 的專案可以裝起來，之後就跟 `spork` 一樣寫：

```sh
cd ~/repo/langs/janet-lab
jpm install                    # 裝到全域 ~/.local/lib/janet/

# 或只裝進某個專案自己的 jpm_tree（不動全域）
cd ~/code/我的專案
jpm -l install git::file:///home/lorkhan/repo/langs/janet-lab
```

```janet
(import llm-http/init :as llm)      # 裝好之後，放在哪一層都這樣寫
```

### ⚠ 從本地 repo 裝有兩個前提

**(a) 那個目錄要先 `git init` 並且至少有一個 commit。** jpm 是用 git clone 的方式抓的，
沒有 commit 就沒東西可 clone。

**(b) bundle 字串裡一定要有冒號**，否則會被當成「官方套件清單裡的短名字」：

```sh
jpm -l install ./libfoo                     # ✗ bundle ... not found
jpm -l install /home/我/libfoo               # ✗ 同上
jpm -l install git::file:///home/我/libfoo   # ✓ 有冒號 → 被當成位址
```

`--local`／`-l` 裝到目前目錄的 `jpm_tree/`，不加就是全域 `~/.local/lib/janet/`。
用 `-l` 的專案跑起來要帶 `jpm_tree`（`jpm -l janet ...`），或讓 jpm 幫你跑。

### ⚠ `declare-source` 的 `:source` 要逐檔列

```janet
(declare-source
  :prefix "llm-http"
  :source ["modules/llm-http/init.janet"      # ← 一支一支列
           "modules/llm-http/chat.janet"])
```

給目錄名不會展開成裡面的檔案，而是整個目錄被 `cp -rf` 過去，變成
`<modpath>/llm-http/llm-http/…`——多包一層，import 路徑就全跑掉了。
