# 47f · 錯誤與成本

打真模型會遇到的狀況，大致就這六種。**其中三種不會丟例外**——這才是重點。

前一篇：[47e 圖像輸入](47e-圖像輸入.md)。
可跑範例（離線，六種全部演一遍）：[`../examples/agent-tutorial/47f-errors.janet`](../examples/agent-tutorial/47f-errors.janet)。

## 一張表

| 狀況 | 怎麼發現 | 怎麼辦 |
|------|----------|--------|
| 連不上 | `http/request` 丟例外 | 後端沒起來／位址寫錯 |
| 401 | HTTP 狀態碼 | 金鑰錯或沒送 |
| 429 | HTTP 狀態碼 | 退避重試 |
| 截斷 | **HTTP 200**，`finish_reason="length"` | 把 `max_tokens` 調大 |
| 推理吃光預算 | **HTTP 200**，`content` 是空字串 | 同上，而且要調得夠大 |
| 模型胡說 | **HTTP 200**，看起來完全正常 | 只能靠你驗證回答 |

## ① 連不上

```
✗ 連不上 http://127.0.0.1:45799/v1/chat/completions：Connection refused
✗ （litellm proxy／LM Studio 起來了嗎？位址一定要用 127.0.0.1 不要用 localhost）
```

⚠ **連本機一律寫 `127.0.0.1` 不要寫 `localhost`**：`localhost` 可能先解到 `::1`，
而 Janet 的 `net/connect` 只取 getaddrinfo 的第一筆，對只聽 IPv4 的後端會直接
connection refused（見 [`../FINDINGS.md`](../FINDINGS.md) 第五節）。

⚠ **`https://` 打不通**，因為 `spork/http` 底層沒有 TLS。這不是設定寫錯，是先天限制
（[17](17-用-spork-http-打-api.md)）。解法見 [47g](47g-接真後端.md)。

## ② 401 與 ③ 429

`http/request` 只在**連不上**時丟例外；對方回 401 對它來說是「成功收到回應」，
所以狀態碼要自己判：

```
✗ HTTP 401（…/v1/chat/completions）：{"error":{"message":"Incorrect API key provided",…}}
✗ HTTP 429（…/v1/chat/completions）：{"error":{"message":"Rate limit reached",…}}
```

401 重試一萬次還是 401；429 才是該重試的那種。

## 重試與逾時

```
  第 1 次失敗，等 0.05 秒再來
  第 2 次失敗，等 0.10 秒再來
  最後拿到：(fake) third time lucky
```

指數退避：第 n 次等 `base * 2^n`。三個一定要記得的點：

- ⚠ **退避要加 jitter**，否則一群 client 同時失敗會同時重試（thundering herd）。
  jitter 別用裸的 `math/random`，它每次跑程式都給同一串（[26](26-隨機數.md)）。
- ⚠ **不是所有錯誤都該重試**。401、參數錯誤、打錯字的 URL——重試只是浪費時間。
- ⚠ **「成功了沒」要用明確的旗標**，不要靠「最後一個錯誤是不是 `nil`」判斷：
  第三次成功時，那個變數還留著第二次的值，於是明明成功卻照樣拋。

能直接抄的完整版（含逾時 `ev/with-deadline`）：
[`../snippets/retry-timeout.janet`](../snippets/retry-timeout.janet)。

## ④⑤ 截斷：HTTP 200，但答案是半截的

```
HTTP 是 200，finish_reason = length，truncated? = true
content = ""   ← 空字串不是 nil，一路過關到你手上
usage   = @{:completion_tokens 8 :completion_tokens_details @{:reasoning_tokens 5}}
```

實測（LM Studio ＋ `google/gemma-4-e4b`）：**推理模型會先把預算花在 `reasoning_tokens` 上**，
`max_tokens` 給小了就什麼都不剩。給到 120 個 token 也一樣——其中 117 個是 reasoning，
`content` 還是空的（[`../FINDINGS-踩坑.md`](../FINDINGS-踩坑.md) 第十節）。

`ask` 遇到這種情況不會回 `""` 給你，它直接講清楚：

```
✗ 答案被 max_tokens 截斷了（finish_reason=length），content 是空字串。
✗ 推理模型會先花掉 reasoning tokens，預算太小就什麼都印不出來——把 max_tokens 調大。
✗ 這次用量：@{:completion_tokens 8 :completion_tokens_details @{:reasoning_tokens 5}}
```

⚠ 更陰的是**截斷但 content 非空**：你會拿到一段讀起來很順、但在句子中間斷掉的答案。
只有 `finish_reason` 講得出來。

## ⑥ 估成本

各家計價單位都是「每百萬 token 多少錢」，輸入與輸出價格不同（輸出通常貴 3～5 倍）。
每次回應的 `usage` 累加起來就是帳單：

```janet
(update 帳 :in  + (get u :prompt_tokens 0))
(update 帳 :out + (get u :completion_tokens 0))
```

```
三次呼叫：輸入 78 token、輸出 27 token
估價 = 0.000028 美元
```

⚠ **tool loop 特別貴**。每一輪都重送整份歷史，所以第 n 輪的輸入包含前 n-1 輪的全部內容——
輸入 token 是平方成長的。一個五輪的 agent 任務，輸入量可能是單次問答的十幾倍。

三個省錢的地方：截斷歷史（[47b](47b-多輪對話.md)）、壓低 `max-rounds`（[47d](47d-自己寫-agent-loop.md)）、
簡單任務用小模型。
