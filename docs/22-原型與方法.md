# 22 · 原型與方法（Janet 版的「類別」）

Janet 沒有 `class`、沒有 vtable、沒有繼承語法。但它有兩個小機制，
拼起來就足以做出你要的 class 效果：**原型鏈**（prototype）跟**方法呼叫語法** `(:method obj)`。

先講結論：**大部分時候你不需要這章**。Janet 的預設做法是「純資料 + 純函式」，
只有在「一群函式共用同一份狀態、而且需要多型」時才值得搬出原型。

## 方法呼叫語法 `(:key obj args...)`

這其實不是什麼特殊機制，只是 keyword 可以當函式用：

```janet
(def t @{:greet (fn [self] (string "hi, " (self :name))) :name "Al"})
(:greet t)          # => "hi, Al"
```

`(:greet t)` 等於 `((get t :greet) t)`——**查出那個 key 的值，然後把物件自己當第一個參數傳進去**。
`self` 沒有魔法，就是個一般參數，名字你要叫 `this` 也行。

你已經在別的章節看過這個語法：`(:read f :line)`、`(:close f)`、`(:write f "x")`。
Janet 的 file、socket 都是這樣做的。

## 原型鏈 = 共用的方法表

table 可以掛一個 prototype。查 key 時**自己沒有就往 prototype 找**，一路往上：

```janet
(def Point                              # 「類別」就是一個放方法的 table
  @{:norm (fn [self] (math/sqrt (+ (* (self :x) (self :x))
                                   (* (self :y) (self :y)))))
    :show (fn [self] (string "(" (self :x) "," (self :y) ")"))})

(defn point [x y]                       # 「建構子」就是個普通函式
  (table/setproto @{:x x :y y} Point))

(def p (point 3 4))
(:norm p)      # => 5
(:show p)      # => "(3,4)"
```

對照 C++：**instance 只放資料成員，prototype 那個 table 就是 vtable + 靜態成員**。
每個 instance 只多一個指向 prototype 的指標，不會複製方法。

### 繼承就是「原型再掛原型」

```janet
(def Point3 (table/setproto @{:show (fn [self] "3d point")} Point))
(def q (table/setproto @{:x 1 :y 2 :z 3} Point3))

(:show q)     # => "3d point"       Point3 蓋掉了 Point 的 show
(:norm q)     # => 2.236...         沒定義就往上找到 Point 的
```

查找順序：`q` → `Point3` → `Point`。就是單一繼承鏈，先找到先贏。
要叫「父類別」的版本，自己往上取：

```janet
(defn show-with-parent [self]
  (string "3D " ((get (table/getproto Point3) :show) self)))
```

沒有 `super` 關鍵字——這是原型系統誠實的地方，你看得到整條鏈。

## ⚠ 三個一定會踩的地方

### ① `get` 會走原型鏈，`keys` / `pairs` / `each` 不會

```janet
(get p :norm)    # => <function>   找得到（走了原型鏈）
(keys p)         # => @[:x :y]     看不到 :norm！
(length p)       # => 2            只算自己的
```

所以「把物件序列化成 JSON」時，方法**自動不會被帶進去**（這通常是好事），
但你若想列舉「這個物件有哪些能力」，得自己往 `table/getproto` 上爬。

### ② prototype 是共用的，改它會影響所有 instance

```janet
(put Point :show (fn [self] "改了"))
(:show p)     # => "改了"    ← 已經建好的 p 也跟著變
```

這是特性不是 bug（等於 runtime patch vtable），但它意味著**別把可變的預設值放進 prototype**：

```janet
(def Bad @{:items @[]})              # ⚠ 所有 instance 共用同一個 array！
(def Good @{:init (fn [self] (put self :items @[]))})   # 建構時各給各的
```

跟 Python class attribute 的經典陷阱一模一樣，C++ 這邊則像誤把成員宣告成 `static`。

### ③ struct 也能有 prototype，但那是給不可變資料用的

```janet
(def s (struct/with-proto {:b 2} :a 1))
s            # => {:a 1}     印出來看不到 proto
(s :b)       # => 2          但查得到
```

實務上很少用；要做物件請用 table。

## 什麼時候該用、什麼時候不該用

| 情況 | 建議 |
|------|------|
| 三個欄位的回傳值 | 直接 `{:ok true :code 200}`，不要建類別 |
| 一組操作同一份設定的函式 | 傳一個 config table 當第一個參數就好 |
| 需要多種實作、呼叫端不想知道是哪種（多型） | 用原型 |
| 資源有狀態、有生命週期（連線、parser） | 用原型 + `:close`，就能配合 `with`（[20](20-錯誤處理與資源管理.md)） |

最後這個最實用——只要你的物件有 `:close` 方法，`with` 就會自動幫你收：

```janet
(def Conn @{:close (fn [self] (print "斷線"))
            :query (fn [self q] (print "查詢 " q))})
(defn connect [] (table/setproto @{:host "x"} Conn))

(with [c (connect)]
  (:query c "select 1"))
# 印出：查詢 select 1  →  斷線
```

## 給 C++ 開發者的一句總結

原型鏈能做到的事情，跟「單一繼承 + 全部 virtual + 可以在 runtime 改 vtable」差不多。
它做不到的是：多重繼承、編譯期檢查、存取控制（沒有 private）。
Janet 沒打算補這些——需要那種結構的程式，通常代表它應該寫在 C 那一側（[10](10-c-互通.md)）。
