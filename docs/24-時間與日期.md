# 24 · 時間與日期

Janet 處理時間的東西只有六個，但**「時間」其實是兩件不同的事**，混用會出很難查的 bug：

| 你要的 | 叫什麼 | 用哪個 |
|--------|--------|--------|
| **某個時間點**（現在幾點、檔案什麼時候改的） | 時間戳 timestamp | `os/time`、`os/date`、`os/mktime`、`os/strftime` |
| **過了多久**（這段程式跑幾秒） | 時長 duration | `os/clock` |

先分清楚，下面兩半各講一種。

## 一、時間點：Unix 秒是唯一的通用貨幣

```janet
(os/time)     # => 1788016918
```

這個數字叫 **Unix 時間戳**：從 1970-01-01 00:00:00 UTC 算起經過幾秒。
它是**整數、沒有時區**——同一瞬間全世界拿到的是同一個數字，時區只在「印給人看」時才出現。

> 心法：**內部一律存 Unix 秒，只在輸出那一刻才轉成人看的樣子。**
> 存字串或存「年月日欄位」都會讓你之後被時區與格式咬。

### 給人看：os/strftime

```janet
(os/strftime "%Y-%m-%d %H:%M:%S" (os/time) true)   # => "2026-08-29 23:21:58"（本地）
(os/strftime "%Y-%m-%d %H:%M:%S" (os/time))        # => "2026-08-29 15:21:58"（UTC）
```

第三個參數是 **local**：**給 `true` 才是本地時間，不給就是 UTC**。這是所有時間函式的
統一慣例（`os/date`、`os/mktime` 也一樣），⚠ **忘了給 = 你的時間會差一個時區**。

`%Y` 年、`%m` 月、`%d` 日、`%H` 時、`%M` 分、`%S` 秒——這些是 C 的 `strftime` 格式碼，
Janet 直接轉給作業系統。**有它就不用自己補零**。

⚠ 但 Janet 只放行**一部分**格式碼，而且**不支援的會直接拋錯、不是印出原字元**：
`%F`（= `%Y-%m-%d`）、`%T`、`%s`、`%D` 這些在別的語言很常見的簡寫，
在這裡通通是 `invalid conversion specifier`。能用的完整清單見
[`reference/os-時間.md`](../reference/os-時間.md)——**寫死在程式裡之前先跑一次確認**。

### 拆成欄位：os/date

要拿「月份」「星期幾」來做判斷時，用 `os/date` 拆成一個 struct：

```janet
(os/date (os/time) true)
# => {:year 2026 :month 7 :month-day 28 :hours 23 :minutes 21 :seconds 58
#     :week-day 6 :year-day 240 :dst false}
```

## ⚠ 這篇最大的坑：月與日是 0-based

上面那筆資料的真實時間是 **2026-08-29 23:21:58**。可是：

- `:month` 是 **7**，不是 8
- `:month-day` 是 **28**，不是 29

**`:month` 和 `:month-day` 從 0 開始數**（跟 C 的 `struct tm` 一樣），
其它欄位（`:year`、`:hours`、`:minutes`、`:seconds`）卻是正常的。所以印給人看要 `+1`：

```janet
(def d (os/date (os/time) true))
(printf "%d-%02d-%02d" (d :year) (inc (d :month)) (inc (d :month-day)))
# => 2026-08-29
```

這個坑的可怕之處在於**它有 11/12 的機率看起來只是「差一點」**：八月印成七月，
你會以為是時區問題而往錯的方向查。**能用 `os/strftime` 就不要自己組字串**——
它幫你算好了，不會有這個問題。

其餘欄位：`:week-day` 星期幾（0 = 星期日）、`:year-day` 一年的第幾天（也 0-based，1/1 是 0）、
`:dst` 是不是日光節約時間（台灣恆為 `false`）。

⚠ 更討厭的是**兩套系統不一致**：同一個時刻，`:year-day` 給你 `240`，
但 `os/strftime` 的 `%j` 給你 `241`（**`%j` 是 1-based**）。兩邊都對，只是基準不同——
拿 `os/date` 的欄位跟 strftime 的輸出對照時會以為自己算錯。

### 反過來：欄位 → Unix 秒

```janet
(os/mktime {:year 2026 :month 7 :month-day 28 :hours 12 :minutes 0 :seconds 0} true)
# => 1787976000
```

`os/mktime` 吃的 struct **也是 0-based**，跟 `os/date` 對稱，所以兩者可以來回轉：

```janet
(os/mktime (os/date (os/time) true) true)   # => 跟 (os/time) 一模一樣
```

### 日期算術：直接加減秒數

Janet 沒有「日期物件」也沒有 `add-days` 這種函式，**因為不需要**——時間戳就是數字：

```janet
(def 一天 86400)
(os/strftime "%Y-%m-%d" (+ (os/time) (* 3 一天)) true)   # 三天後 => "2026-09-01"
```

跨月、跨年、閏年全部自動對，因為你算的是秒，換算的工作交給 `os/strftime`。

> ⚠ 唯一要小心的是**日光節約時間**的地區：那裡「一天」不一定是 86400 秒。
> 台灣沒有這個問題；要處理有 DST 的時區，改成用 `os/date` 拆開、`:month-day` 加一、
> 再 `os/mktime` 轉回去，讓作業系統處理。

## 二、時長：計時要用 os/clock

```janet
(def t0 (os/clock :monotonic))
(做某件事)
(printf "花了 %.3f 秒" (- (os/clock :monotonic) t0))
```

`os/clock` 回的是**帶小數的秒數**（`os/time` 只到秒，計時不夠用）。三種來源：

| 來源 | 是什麼 | 什麼時候用 |
|------|--------|-----------|
| `:realtime`（預設） | 牆上時鐘，就是 Unix 秒的浮點版 | 要「現在幾點」的高精度版 |
| `:monotonic` | **單調時鐘**：從某個任意時間點起單調遞增 | **計時一律用這個** |
| `:cputime` | 這個行程實際用掉的 CPU 時間 | 想知道「真的在算」而不是在等 IO |

「**單調**」的意思是**它保證只會往前、不會倒退**。`:realtime` 會被 NTP 校時、
使用者手動改時鐘、日光節約切換給改掉——如果剛好在你計時的中間發生，
你會算出**負數的耗時**。`:monotonic` 不掛在牆上時鐘上，所以不會。

⚠ `:monotonic` 的數值**本身沒有意義**（實測拿到 `59881.39`，那是開機到現在的秒數之類的東西），
只有「兩次相減」才有意義。不要拿它當時間點存起來。

## 暫停：os/sleep 與 ev/sleep

```janet
(os/sleep 0.05)   # 擋住整個行程 0.05 秒
(ev/sleep 0.05)   # 只擋住目前這條 fiber，其他 fiber 照跑
```

寫單純的腳本用 `os/sleep`；只要程式裡有 `ev/` 的東西（channel、net、非同步 IO），
就要用 `ev/sleep`，否則你會把整台事件迴圈凍住。差別見
[15 ev：channel / 執行緒](15-ev-channel-net.md)。
