# 47b · system prompt 與多輪對話

**模型不記得你。** 它每次收到的就只有你這次送過去的那個 `messages` 陣列，
講完就忘。所謂「記憶」是你自己在維護一個陣列，每輪都把整份重送一次。

前一篇：[47 LLM API 到底是什麼](47-llm-api-是什麼.md)。
可跑範例（離線）：[`../examples/agent-tutorial/47b-multi-turn.janet`](../examples/agent-tutorial/47b-multi-turn.janet)。

## 一輪對話要做三件事

```janet
(defn 問 [cfg 歷史 說什麼]
  (array/push 歷史 @{:role "user" :content 說什麼})      # ① 把人講的加進去
  (def 答 (llm/reply-text (llm/chat cfg 歷史)))           # ② 整份送出去
  (array/push 歷史 @{:role "assistant" :content 答})      # ③ 把它的回答也記回去
  答)
```

③ 最容易漏。漏了的話下一輪模型看不到自己上一句說過什麼，對話會一直跳針。

## 實測：同一個問題，差別只在有沒有帶歷史

範例裡的假後端規則很笨——它只在**這次收到的 messages 裡**找「名字是小明」這句話。
就是要讓「記憶從哪來」無所遁形：

```
── ① 不帶歷史：每次都是第一次見面 ────
  你 → 我的名字是小明。
  模 → （假後端）你叫小明。   （這次送出 1 則訊息，prompt_tokens=4）
  你 → 我叫什麼名字？
  模 → （假後端）我不知道你的名字。   （這次送出 1 則訊息，prompt_tokens=4）

── ② 帶歷史：同一個陣列一直長 ──────────
  你 → 我的名字是小明。
  模 → （假後端）你叫小明。   （這次送出 1 則訊息，prompt_tokens=4）
  你 → 我叫什麼名字？
  模 → （假後端）你叫小明。   （這次送出 3 則訊息，prompt_tokens=12）
  歷史現在 4 則：user → assistant → user → assistant
```

第二輪送出去的是 3 則、`prompt_tokens` 從 4 變 12。**這就是記憶的全部實作。**

## system prompt

`system` 就是插在陣列最前面的一則訊息，用來設定模型的身分、語氣、輸出格式。
它跟其他訊息一樣**每輪都要重送**——它不是「設定一次就生效」的開關。

```
── ③ system prompt：插在最前面，每次都要重送 ──
  你 → 我的名字是小明。
  模 → （假後端）回稟主人，您叫小明。   （這次送出 2 則訊息，prompt_tokens=8）
```

三種給法，選順手的：

```janet
(llm/ask cfg "問題" "你是古代的管家，講話很恭敬。")          # ask 的第二個參數
(llm/with-tools cfg 歷史 tools handlers :system "…")         # tool loop 的具名參數
(array/insert 歷史 0 @{:role "system" :content "…"})         # 自己組
```

⚠ **`with-tools` 的 `:system` 在歷史第一則已經是 system 時會被忽略**，
避免一次送出兩則 system 讓模型無所適從。要換掉原本那則就自己改 `messages`。

## 歷史會無限長大

每輪都重送整份，所以 `prompt_tokens` 是累加的——對話越長越慢也越貴，
長到超過模型的 context 上限就直接報錯。**你一定要有截斷策略。**

最簡單的一種：留住 system，其餘只留最後 n 則。

```janet
(defn 截斷 [歷史 n]
  (def sys (if (= "system" (get-in 歷史 [0 :role])) [(歷史 0)] []))
  (def 其餘 (array/slice 歷史 (length sys)))
  (array ;sys ;(array/slice 其餘 (- (inc (min n (length 其餘)))))))
```

⚠ **`array/slice` 的負索引是「從尾端算，-1 指向結尾之後」**，
要拿最後 n 個得寫 `(- (inc n))` 不是 `(- n)`：

```janet
(array/slice @[1 2 3 4 5] -3)   # => @[4 5]
(array/slice @[1 2 3 4 5] -2)   # => @[5]
```

拿最後 2 個要給 `-3`，也就是 `(- (inc n))`。

寫錯會少拿一個，而且少拿的那個通常剛好是一對訊息的前半（見下一條）。

實測（範例第 ④ 段）：

```
  截斷前 11 則：S 第 0 句 回 0 第 1 句 回 1 第 2 句 回 2 第 3 句 回 3 第 4 句 回 4
  截斷後 5 則：S 第 3 句 回 3 第 4 句 回 4
```

⚠ **一次砍一對，別砍單數**。assistant 的 `tool_calls` 與它對應的 `role:"tool"` 訊息
是綁在一起的（[47c](47c-tool-calling.md)），切開了下一次請求就對不起來，
有些後端會直接回 400。

其他做法（這裡不展開，知道有就好）：把舊對話叫模型摘要成一段 system、
或按 token 數而不是則數來砍。
