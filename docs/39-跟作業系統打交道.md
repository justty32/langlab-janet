## 我現在在什麼機器上

```janet
(os/which)      # => :linux    也可能是 :windows :macos :bsd …
(os/arch)       # => :x64
(os/compiler)   # => :gcc      這份 janet 是誰編的
(os/cpu-count)  # => 16        決定要開幾條執行緒（見 15 ev）
```

`os/which` 是**寫跨平台程式碼的分歧點**。本 repo 的 Windows 坑幾乎都能用它繞：

```janet
(def 換行 (if (= :windows (os/which)) "\r\n" "\n"))
```

## ⚠ `os/shell` 回的不是 exit code

這個最容易寫錯，因為它看起來就該回 exit code：

| 子行程 exit | `(os/shell "exit N")` | `(os/execute ["sh" "-c" …] :p)` |
|------------|----------------------|--------------------------------|
| 0 | `0` | `0` |
| 1 | **`256`** | `1` |
| 3 | **`768`** | `3` |
| 7 | **`1792`** | `7` |

`os/shell` 回的是 C `system()` 的**原始 wait status**，也就是 `exit code × 256`。
它的 docstring 對回傳值**一個字都沒提**。

所以 `(= 0 (os/shell …))` 剛好能用（成功都是 0），但
**`(= 1 (os/shell "exit 1"))` 永遠是 false**。而且這個編碼是 POSIX 的，Windows 上不一樣。

> **結論：要判斷成敗就用 `os/execute`**（[11](11-pipeline-signal.md) 那篇的主角），
> 它回的是乾淨的 exit code，而且不經過 shell、不用煩惱引號跳脫。
> `os/shell` 只適合「跑一下、不管結果」的場合。

## `os/isatty`：輸出是接到人還是接到管線

```janet
(os/isatty stdout)
```

直接在終端機跑 → `true`；被 `| cat` 或 `> 檔案` 導走 → `false`。實測：

```
$ janet t.janet | cat      →  isatty stdout=false
$ janet t.janet            →  isatty stdout=true
```

這是**寫 CLI 工具時該問的第一個問題**：接到人就可以上色、畫進度條、清行；
接到管線就要輸出乾淨的純文字，否則下游會吃到一堆 ANSI 逃脫碼。

```janet
(def 上色? (os/isatty stdout))
(defn 紅 [s] (if 上色? (string "\e[31m" s "\e[0m") s))
```

⚠ 分開判斷 `stdout` 與 `stderr`——常見情況是 stdout 被導走、stderr 還在終端機上。

## 權限：三個函式互相翻譯

```janet
(os/perm-string 8r644)      # => "rw-r--r--"
(os/perm-int "rw-r--r--")   # => 420          ← 十進位的 8r644
(os/chmod "檔案" 8r644)      # 兩種寫法都吃
```

### ⚠ Janet 沒有八進位字面值

```janet
0o644    # ✘ parse error: symbol literal cannot start with a digit
0644     # ✘ 這是十進位的 644，不是權限！
8r644    # ✓ 正確寫法
```

Janet 用 **`基數r數字`** 的通用寫法：`8r644`（八進位）、`16rFF`（十六進位 255）、
`2r1010`（二進位 10）。從 C 過來的人打 `0644` 不會報錯——它就是**十進位 644**，
悄悄設成完全不同的權限。要寫權限**一定加 `8r`**，或乾脆用 `"rw-r--r--"` 字串版。

## 檔案操作補完

[19b](19b-檔案系統與路徑.md) 講了 `os/stat`、走目錄、`spork/path`。剩下這些：

| 函式 | 做什麼 | 備註 |
|------|--------|------|
| `os/realpath` | 解開 `..`、symlink，給絕對路徑 | 檔案**必須存在**，否則報錯 |
| `os/readlink` | 讀 symlink 指向哪 | 不解析，只讀一層 |
| `os/rename` | 改名／搬移 | 同一個檔案系統內才是原子操作 |
| `os/touch` | 更新 mtime（檔案不存在**不會**幫你建）| 可指定時間 |
| `os/rmdir` | 刪空目錄 | 非空會報錯；要遞迴刪自己走 |
| `os/link` / `os/symlink` | 硬連結／符號連結 | ⚠ Windows 上限制多 |
| `os/umask` | 設定新檔的預設權限遮罩 | 影響**之後**建的檔 |

⚠ 這一整組在 Windows 上行為都不同（權限模型不一樣、symlink 要特權）。
凡是宣稱「Windows 上會怎樣」的，都要實機驗過再寫——本 repo 的做法見
[FINDINGS-踩坑b-工具鏈.md](../FINDINGS-踩坑b-工具鏈.md)。

`os/posix-fork`、`os/posix-exec`、`os/posix-chroot` 顧名思義**只有 POSIX 有**，
在 Windows 上根本不存在，用之前先問 `os/which`。
