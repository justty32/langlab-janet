# 21 · 數字與位元運算

這篇對 C++ 開發者特別重要，因為 Janet 的數字模型跟你的直覺**差很多**：
沒有 `int`、`long`、`unsigned`，只有一種 `:number`，而它是 **IEEE 754 double**。

```janet
(type 3)      # => :number
(type 3.5)    # => :number     兩者同型別
(= 3 3.0)     # => true        沒有整數 / 浮點的分別
```

## 第一個後果：整數精度只到 2^53

double 的尾數是 53 bit，超過就開始掉精度——跟 C++ 的 `int64_t` 完全不同：

```janet
9007199254740993          # => 9.00719925474099e+15   ← 精度沒了，還被印成科學記號
(+ 1e308 1e308)           # => inf                    ← 溢位變 inf，不是 UB
(/ 1 0)                   # => inf                    ← 不會拋錯！
(/ 0 0)                   # => -nan(ind)（Windows 上的印法）
```

⚠ **`(/ x 0)` 不會拋例外**，它給你 `inf`。C++ 整數除以零是 UB、會 crash；
Janet 靜靜回一個 `inf` 然後污染後面所有計算。要防就自己檢查除數。

## 除法：`/` `div` `mod` `%` 四個都不一樣

```janet
(/ 7 2)      # => 3.5    永遠是浮點除法（C++ 的 int/int 截斷在這裡不存在）
(div 7 2)    # => 3      整數除法（往下取整）
(mod -7 2)   # => 1      結果跟「除數」同號（數學上的模）
(% -7 2)     # => -1     結果跟「被除數」同號（C++ 的 % 是這個）
```

從 C++ 過來只要記兩件事：**`/` 不截斷，要截斷用 `div`；`%` 才是你熟的 `%`，`mod` 不是。**

取整另外有 `math/floor`、`math/ceil`、`math/trunc`、`math/round`：

```janet
(math/floor -3.5)   # => -4    往負無窮
(math/trunc -3.5)   # => -3    往零（C++ 轉型的行為）
(math/round 2.5)    # => 3     .5 一律遠離零，不是銀行家捨入
```

## 真的需要 64 位元整數：int/s64 與 int/u64

```janet
(int/s64 "9007199254740993")   # => <core/s64 9007199254740993>   精度保住了
(+ (int/s64 9) 1)              # => <core/s64 10>   跟 number 混算會自動轉
(type (int/s64 1))             # => :core/s64       ⚠ 不是 :number
(int/to-number (int/s64 5))    # => 5               轉回 double
```

用在：檔案大小 / 時間戳 / 雜湊值 / 跟 C 的 `int64_t` 介面（FFI，見 [10b](10b-ffi-型別與指標.md)）。

⚠ 大數字**一定要用字串建構**：`(int/s64 9007199254740993)` 這個字面值在被 `int/s64` 看到之前
就已經是掉過精度的 double 了。寫成字串才能繞過。

⚠ `(type x)` 回的是 `:core/s64` 不是 `:number`，所以 `(number? x)` 是 false。
要判斷「是不是數值」在混用 s64 時得自己多一層檢查。

## 位元運算是 32 位元的，不是 64

這是最容易靜默出錯的一個。所有 `b*` 系列運算都**在 signed 32-bit 上做**：

```janet
(band 12 10)     # => 8      AND
(bor 1 2)        # => 3      OR
(bxor 5 3)       # => 6      XOR
(bnot 0)         # => -1     NOT（signed，所以是 -1 不是 0xFFFFFFFF）
(blshift 1 8)    # => 256
(blshift 1 31)   # => -2147483648   ⚠ 溢位成負數
(blshift 1 32)   # => 1             ⚠ 位移量取 mod 32，不是 0！
(blshift 1 40)   # => 256           ⚠ 等於 1 << 8
(brshift -8 1)   # => -4     算術右移（補號位）
(brushift 8 1)   # => 4      邏輯右移（補 0）；⚠ 負數會直接報錯
```

C++ 裡 `1 << 32` 是 UB、`1u << 40` 你會用 `uint64_t` 解決；Janet 這裡是
**靜默地把位移量對 32 取餘數**，結果看起來很合理但完全不是你要的。

### 解法：把運算元換成 int/u64，同一批函式就變 64 位元

```janet
(blshift (int/u64 1) 40)    # => <core/u64 1099511627776>   ← 對了
(blshift (int/s64 1) 40)    # => <core/s64 1099511627776>
(band (int/u64 12) (int/u64 10))   # => <core/u64 8>
(bnot (int/u64 0))          # => <core/u64 18446744073709551615>  完整 64 bit 遮罩
```

所以規則是：**位元寬度取決於運算元的型別**，plain number 走 32-bit signed，
`int/s64`／`int/u64` 走 64-bit。要做雜湊、協定欄位、大遮罩，第一件事就是把值包成 `int/u64`。

⚠ `(int/u64 -1)` 會直接報錯（不能轉負數）。想要「全 1」請用 `(bnot (int/u64 0))`。

## 數字字面值的寫法

```janet
0x1F            # => 31      十六進位
2r1010          # => 10      任意進位：<base>r<digits>
16rFF           # => 255
1_000_000       # => 1000000 底線分隔，純粹好讀
1e-3            # => 0.001
```

`<base>r<digits>` 這個語法 C++ 沒有，寫二進位遮罩時很好用：`2r1000_0001`。

## 型別判斷與轉換

```janet
(number? 3)         # => true
(int? 3)            # => true    是否為整數值（3.5 → false）
(int? 3.5)          # => false
(nat? 3)            # => true    非負整數
(scan-number "42")  # => 42      字串轉數字，失敗回 nil（不拋錯）
(string 42)         # => "42"
```

`scan-number` 是安全版 `std::stoi`：不合法就 `nil`，直接拿去接 `if-let` 很順。

## 比較與排序

```janet
(< 1 2 3)              # => true    可以接多個參數，等於 1<2 且 2<3
(compare 1 2)          # => -1      通用三向比較（像 C++20 的 <=>）
(compare "a" "b")      # => -1      字串也能比
(sorted @[3 1 2])      # => @[1 2 3]           回新的
(sort @[3 1 2])        # => @[1 2 3]           就地改，同時回傳它
(sorted-by |(- $) @[3 1 2])   # => @[3 2 1]    自訂 key
```

⚠ 「會不會改到原資料」的命名規則有兩套，別搞混：

| 回新的 | 就地改 |
|--------|--------|
| `sorted` | `sort` |
| `reverse` | `reverse!` |

**`!` 結尾＝就地**是通則，但 `sort`／`sorted` 是例外（`sort` 才是就地那個）。
不確定時就查 `(doc sort)`。
