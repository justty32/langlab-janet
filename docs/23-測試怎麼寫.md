# 23 · 測試怎麼寫

[05 jpm 與專案](05-jpm-與專案.md) 教了怎麼**跑** `jpm test`，這篇教怎麼**寫**。

先講最重要的觀念：**Janet 沒有測試框架**。沒有 `describe` / `it`、沒有 `@Test`、
不用註冊、不用繼承任何東西。一支測試就是**一支普通的 Janet 程式**，規則只有一條：

> **正常跑完 = 通過；中途出錯讓行程以非 0 結束 = 失敗。**

所以你已經會寫測試了——會寫 `.janet` 就會。剩下的都是慣例。

## jpm test 到底做了什麼

```sh
jpm test
```

它把 `test/` 底下**每一支 `.janet` 檔**各自**用一個獨立的 janet 行程**跑一遍
（依檔名排序），然後看每支的 exit code。就這樣，沒有別的魔法。

「獨立行程」這點很重要，兩個後果：

- 測試之間**不共享狀態**。A 檔改了某個全域，B 檔看不到——這是好事，測試不會互相汙染。
- 每支都要**自己 import 它要測的東西**，不能指望別人先載好。

## 最小的一支測試

```janet
# test/math.janet
(assert (= 4 (+ 2 2)) "2+2 應該是 4")
(print "math 測試通過 ✓")
```

`assert` 就是全部：條件為假就丟錯、行程以非 0 結束、`jpm test` 記你一筆失敗。
最後印一行「通過」是本 repo 的慣例——`jpm test` 成功時很安靜，
有這行才看得出「它真的跑到底了」而不是中途悄悄跳過。

## assert 的三個事實

```janet
(assert 5 "訊息")        # => 5      ← 回傳的是「被檢查的值」，不是 true
(assert nil "壞了")      # 丟錯，錯誤訊息就是 "壞了"
(assertf (= 1 2) "期望 %d 但拿到 %d" 1 2)   # 訊息要組字串時用 assertf
```

第一點常被忽略但很好用：`assert` 回傳原值，所以可以**串在資料流中間**當「順便檢查」：

```janet
(def cfg (assert (load-config) "設定檔載不進來"))   # 檢查完直接往下用
```

⚠ **第二個參數不要省**。省了也會有訊息，但只有**運算式長什麼樣**：

```
(assert (= 1 2))        # => assert failure in (= 1 2)
(assert (= 1 2) "月份要 0-based")  # => 月份要 0-based
```

`assert failure in (= 1 2)` 告訴你「哪一行壞了」，卻沒告訴你「壞了代表什麼」。
半年後回來看，後者才救得了你。

## 失敗長什麼樣（實測）

三支測試，中間那支故意寫錯：

```
running test/a-good.janet ...
a-good 通過 ✓
running test/b-bad.janet ...
error: 1 應該等於 2
  in thunk [test/b-bad.janet] (tail call) on line 1, column 1
non-zero exit code in test/b-bad.janet: 1
running test/c-after.janet ...
c-after 有沒有被跑到？
✘ Failing test scripts: 1
```

`jpm test` 自己的 exit code 是 **1**（給 CI 用）。三件事讀得出來：

1. 錯誤訊息就是你給 `assert` 的那個字串，加上**檔名與行號**。
2. **一支失敗不會擋住後面的**——`c-after` 照跑。所以一次就能看到全部災情。
3. 但**同一支檔案裡**，失敗那行之後的就不跑了（`b-bad.janet` 的 `print` 沒印出來）。
   所以一支檔案裡塞太多不相關的斷言，第一個壞掉會遮住後面的問題。

## 常用的三種斷言配方

**比較集合**用 `deep=`，不要用 `=`——`=` 對 array／table 比的是「同一個物件嗎」，
兩個內容一樣的陣列它會說不等：

```janet
(assert (deep= @[1 2] @[1 2]) "內容相同")   # ✓
(assert (= @[1 2] @[1 2]) "這條會失敗")      # ✘ 不同物件
```

**斷言「這件事該失敗」**用 `protect`，它把例外接下來變成 `[成功? 值]`——
成功時是 `[true 回傳值]`，失敗時是 `[false 錯誤訊息]`：

```janet
(defn parse-port [s]
  (or (scan-number s) (error "port 不是數字")))

(def [ok e] (protect (parse-port "abc")))
(assert (not ok) "壞輸入本來就該爆")
(assert (= e "port 不是數字") "錯誤訊息要講人話")
```

⚠ 挑「該失敗」的例子時小心：**Janet 很多你以為會爆的事其實不會爆**。
`(/ 1 0)` 回的是 `inf` 不是錯誤（數字全是 double，見
[21 數字與位元](21-數字與位元.md)），`(get nil :a)` 回 `nil` 也不報錯。
拿這種當「該失敗」的測試，會寫出一條**永遠不會紅**的假測試。

本 repo 把這個包成了 [`test/util.janet`](../test/util.janet) 的 `err-of`，
順便回傳錯誤訊息，好驗「**錯誤訊息是不是人看得懂的中文**」：

```janet
(import ./util :as u)
(assert (string/find "缺 :model" (u/err-of |(llm/endpoint {:base "http://x"}))))
```

**測數字**別直接 `=` 浮點數（見 [21 數字與位元](21-數字與位元.md)），比差值：

```janet
(assert (< (math/abs (- got 0.3)) 1e-9) "浮點數要比差值")
```

## ⚠ 兩個這個 repo 踩過的坑

**一、`test/` 底下的「共用工具檔」也會被當測試跑一遍。**
`jpm test` 不管你這支是不是工具，看到 `.janet` 就跑。所以共用檔**只能有定義、
不能有會印東西或有副作用的頂層程式碼**——被單獨跑到時它應該什麼都不做。
[`test/util.janet`](../test/util.janet) 開頭那段註解記的就是這件事。

**二、有副作用的「自動載入」會讓測試在你機器上過、在別人機器上掛。**
本 repo 的模組會在 `import` 時自動去讀 `~/.config/…` 的設定檔；開發機上剛好有一份，
測試結果就跟別人不一樣了。解法是測試開頭先呼叫 `reset-endpoints!` 這類函式歸零
（細節見 [FINDINGS-踩坑.md](../FINDINGS-踩坑.md) 第八節）。

> **本 repo 的測試原則：一律離線。**不打網路、不呼叫真模型。要測 HTTP 就在同一個
> 行程裡起一台假伺服器（做法見 [`test/llm-http-server.janet`](../test/llm-http-server.janet)）。
> 會因為別人家網路而變紅的測試，久了大家就會忽略它。
