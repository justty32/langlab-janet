# 35 · 拷貝與凍結

[01b 給 C++ 開發者](01b-給-C++-開發者.md) 講了 Janet **沒有值拷貝**：`(def b a)` 只是
多一個名字指向同一個物件，沒有拷貝建構子、沒有 `operator=`。

這篇回答接下來那個問題：**那我真的要一份自己的，怎麼拿？**

## 三個層次

| 你要的 | 怎麼做 | 內層跟著複製嗎 |
|--------|--------|---------------|
| 同一個物件、只是換個名字 | `(def b a)` | ——（根本沒複製）|
| **淺**拷貝：外層新的、內層共用 | `(table/clone t)`、`(array/slice a)` | ✘ |
| **深**拷貝：從裡到外都是新的 | `(thaw (freeze x))` | ✓ |
| **凍結**：從裡到外都變成不可變 | `(freeze x)` | ✓（並且換型別）|

## ⚠ `table/clone` 是淺的

```janet
(def 原 @{:a @[1 2]})
(def 淺 (table/clone 原))
(array/push (原 :a) 99)
(淺 :a)   # => @[1 2 99]     ⚠ 跟著變了——內層是同一個 array
```

外層 table 是新的（往 `淺` 塞新的鍵不會影響 `原`），但 `:a` 底下那個 array
**兩邊指的是同一個**。C++ 的預設拷貝建構子對 `std::vector<std::vector<int>>` 是深的，
Janet 這裡**不是**——這是最容易被燙到的地方。

## `freeze`：深度轉成不可變，順便換型別

```janet
(def 凍 (freeze @{:a @[1 2] :b @"x"}))
(type 凍)          # => struct    ← 不是 table 了
(type (凍 :a))     # => tuple     ← 不是 array 了
```

`freeze` **遞迴地**把每一層的可變型別換成對應的不可變型別：

| 可變 | → 凍結後 |
|------|---------|
| `table` `@{}` | `struct` `{}` |
| `array` `@[]` | `tuple` `()` |
| `buffer` `@""` | `string` `""` |
| 其他（數字、keyword、函式…）| 原樣不動 |

函式不會被拒絕也不會被改，`freeze` 就讓它留在那裡。已經是不可變的東西丟進去也沒事，
原樣回來。

⚠ **型別換掉是有後果的**：凍結後 `(array/push … )` 當然不能用，但更容易忘的是
[32 講的 `case`](32-條件與模式比對.md)——`case` 拿 `=` 比，
**struct／tuple 比內容、table／array 比身分**，所以凍結前後的比較行為會突然不一樣。

## `thaw`：解凍，而且是深的

```janet
(def 解 (thaw 凍))
(type 解)        # => table
(type (解 :a))   # => array
```

所以 **深拷貝就是「凍起來再解開」**：

```janet
(def 深 (thaw (freeze 原)))     # 從裡到外全新，跟 原 完全脫鉤
```

繞一圈看起來很怪，但它是 Janet 慣用的深拷貝寫法——因為 `freeze` 保證走遍每一層。

### 另一條路：`marshal` 來回

```janet
(def 深2 (unmarshal (marshal 原)))
```

兩者都給你獨立的一份，內層型別也都保持 `array`。差別：

| | `thaw ∘ freeze` | `unmarshal ∘ marshal` |
|---|---|---|
| 速度 | 快 | 慢（要序列化成 bytes 再讀回來）|
| 循環參照 | ⚠ **無限迴圈卡死** | ✓ 處理得了 |
| 閉包／fiber | 原樣共用（沒複製）| **真的複製一份**（見 [16](16-marshal-與自省.md)）|
| 跨行程 | ✘ | ✓ 那本來就是它的用途 |

⚠ **循環參照那格要特別小心**：`(def c @{}) (put c :self c)` 再 `(freeze c)`
**不會報錯，會直接卡死**（實測跑到 timeout 才停）。它遞迴地走每一層，而那個結構沒有底。
`marshal` 認得已經看過的物件，所以同一份資料它處理得掉。

**平常用 `thaw ∘ freeze`**；資料裡可能有循環參照、或你真的需要連閉包狀態一起複製，才用 marshal。

## 什麼時候該凍

Janet 的慣例是**能不可變就不可變**，理由跟 C++ 用 `const` 一樣，但多一條：

1. **當成常數表**：內建的設定、對照表用 `{}` 而不是 `@{}` 寫，別人改不到。
2. **當字典的鍵**：`table`／`array` 不能拿來當鍵的可靠依據（它們比身分），
   `struct`／`tuple` 可以（比內容）。要用複合鍵就 `freeze` 一下。
3. **要跨 fiber／執行緒傳**：不可變的東西不會被別人在你背後改掉
   （見 [15 ev](15-ev-channel-net.md)）。

反過來，**回傳給呼叫端讓他繼續加工的東西留可變**——不然他每加一筆就要重建一次。
本 repo 的 `modules/llm-http` 就是這樣分的：內建 endpoint 資料是 `struct`（凍的），
組出來要送出去的 payload 是 `table`（可變的）。

janet examples/copy-freeze.janet
