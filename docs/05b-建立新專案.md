# 05b · 建立新專案（`jpm new-*`）與 `main` 的隱藏規則

[← 05 jpm 與專案結構](05-jpm-與專案.md)｜下一篇：[05c jpm 的 rule 系統](05c-jpm-的-rule-系統.md)

## ⚠ 不是 `jpm new`，是 `jpm new-project`

從 cargo／npm 過來的人第一次都會打 `jpm new`，然後得到「unknown command」。
實際有三個 scaffold 指令，差在**產出來的骨架要拿來做什麼**：

| 指令 | 產出 | 什麼時候用 |
|------|------|-----------|
| `jpm new-project 名字` | 純 Janet 的**函式庫**骨架（`declare-source`） | 寫一個給別人 `import` 的模組 |
| `jpm new-exe-project 名字` | 多一個 `declare-executable` 與 `bin/` | 要編出**執行檔** |
| `jpm new-c-project 名字` | 多 `src/*.c` 與 `declare-native` | 要用 C 寫 native 模組（見 [10d](10d-native-與嵌入.md)） |

```sh
cd ~/code
jpm new-exe-project 我的工具
```

會**互動問你** author、description、license 之類的欄位，直接按 Enter 用預設值也行；
答完就長出目錄。產出的 `project.janet` 就是 [05](05-jpm-與專案.md) 講的那三個宣告。

⚠ **`jpm new-project` 生出來的東西沒有 `bin/`、也沒有 `declare-executable`**。
它是函式庫骨架，`jpm build` 不會產出任何執行檔——這不是壞掉，是你挑錯指令了。

## ★ `main` 會被自動呼叫（Janet 的隱藏規則）

`jpm new-project` 生的骨架沒有 `declare-executable`，但你 `janet 那支檔.janet`
還是會看到東西被印出來。原因是 **Janet CLI 的一條通用規則**：

> 用 `janet 檔案.janet` 直接執行一支檔案時，**檔案載入完之後**，
> 如果環境裡有一個叫 `main` 的綁定，Janet 會自動呼叫它，並把命令列參數傳進去。

```janet
# hello.janet
(defn main [& args]
  (print "跑起來了，收到參數：" (string/join (drop 1 args) " ")))
```

```sh
janet hello.janet a b        # → 跑起來了，收到參數：a b
```

`args` 的**第 0 個是腳本／執行檔自己**，你的參數從第 1 個開始——跟 C 的 `argv` 一樣。

這條規則的三個後果，每一個都會咬人：

1. **不用 `declare-executable` 也能跑。** 開發期直接 `janet 檔案.janet` 就好，
   `jpm build` 只在要交付執行檔時才需要。
2. **`use` 進來的 `main` 也算。** 測試檔如果 `(use ../我的專案/init)`，
   那支 init 的 `main` 會被一起帶進環境，於是 `jpm test` 會莫名其妙把 main 印出來。
   要避免就改用 `(import ...)`（有前綴，不會污染環境）。
3. **頂層程式碼比 `main` 還早跑。** 頂層的 `(print ...)`／網路呼叫在**檔案一被載入**
   時就執行，連 `import` 你這支檔案的人也會跑到。真的只想在執行時發生，就搬進 `main`。

```janet
(print "我在載入時就跑了")      # ← import 這支檔案的人也會看到
(defn main [& args]
  (print "我只在直接執行時跑"))
```
