# 33 · 函式參數與閉包

[01 語言速成](01-語言速成.md) 教了 `(defn f [x] …)`。這篇補完參數的**五種形式**，
以及閉包到底捕獲了什麼——後者是從 C++ 過來最容易誤會的地方。

## 五種參數形式

| 寫法 | 意思 | 呼叫端長怎樣 |
|------|------|-------------|
| `[x y]` | 必要參數 | `(f 1 2)` |
| `[x &opt y]` | `y` 可省略，省了就是 `nil` | `(f 1)`、`(f 1 2)` |
| `[x & rest]` | 剩下的全收進 **tuple** | `(f 1 2 3)` → `rest` 是 `(2 3)` |
| `[x &named port host]` | 具名參數，**各自綁成變數** | `(f 1 :port 80 :host "h")` |
| `[x &keys kw]` | 具名參數，**全收進一個 struct** | `kw` 是 `{:port 80 :host "h"}` |

```janet
(defn a [x &opt y] [x y])
(a 1)      # => (1 nil)
(a 1 2)    # => (1 2)
```

`&opt` **沒有預設值語法**，省略就是 `nil`。要預設值用 `default`：

```janet
(defn b [x &opt y]
  (default y 99)      # y 是 nil 才設成 99
  [x y])
(b 1)   # => (1 99)
```

⚠ `default` 看的是 `nil`，不是「有沒有傳」。呼叫端明確傳 `nil` 也會被補成 `99`。

### `&named` 還是 `&keys`？

```janet
(defn d [x &named port host] [x port host])
(d 1 :port 80)               # => (1 80 nil)   沒給的就是 nil

(defn e [x &keys kw] [x kw])
(e 1 :port 80 :host "h")     # => (1 {:host "h" :port 80})
```

**參數名字固定就用 `&named`**（省一次 `get`，而且打錯名字時你自己看得出來）；
**要原封不動轉手給別人**就用 `&keys`（一個 struct，直接 `merge` 或往下傳）。

## ⚠ arity 是**編譯期**檢查，`try` 攔不到

```janet
(defn a [x &opt y] [x y])
(try (a) ([err] err))
# compile error: <function a> expects at least 1 argument, got 0
```

這在動態語言裡很少見——**參數個數不對，整支檔案根本編不起來**，
而且 `try` 包不住它（`try` 是執行期的，錯誤發生在那之前）。
從 C++ 過來的人反而會覺得親切：這比較像編譯器擋下來，不像 Python 跑到那行才炸。

繞過編譯期檢查的只有動態呼叫，這時才變成可以 `try` 的執行期錯誤：

```janet
(try (apply a []) ([err] err))
# => "<function a> called with 0 arguments, expected 2"
```

⚠ 注意那句 `expected 2`——`y` 明明是可選的，訊息卻報最大 arity。**別把它當成「非給兩個不可」**。

## 閉包：捕獲的是**綁定**，不是當下的值

C++ 的 lambda 要你明講捕獲方式：`[n]` 拷貝一份、`[&n]` 抓參考。
**Janet 沒有這個選擇——永遠是抓那個綁定本身**，比較接近 C++ 的 `[&]`。

```janet
(defn 做計數器 []
  (var n 0)
  (fn [] (++ n)))          # 這個 fn 抓住的是外層那個 n

(def c1 (做計數器))
(def c2 (做計數器))
(c1) (c1) (c1)   # => 1, 2, 3
(c2)             # => 1     ← 各自一份，互不干擾
```

跟 C++ 的 `[&]` 有一個關鍵差別：**這裡沒有懸空參考**。`做計數器` 回傳後那個 `n`
照樣活著，因為 Janet 有 GC——閉包持有它，它就不會被回收。
C++ 裡對區域變數用 `[&]` 再回傳 lambda 是 UB，Janet 裡這是**標準寫法**。

### ⚠ 在迴圈裡建閉包：`def` 每圈一份，`var` 全體共用

```janet
(def fs (seq [i :range [0 3]] (fn [] i)))
(map |($) fs)     # => @[0 1 2]    ✓ 每圈一個新的 i

(def gs @[])
(var j 0)
(while (< j 3) (array/push gs (fn [] j)) (++ j))
(map |($) gs)     # => @[3 3 3]    ⚠ 三個閉包抓的是同一個 j
```

`loop`／`seq`／`each` 的綁定**每圈都是新的**，所以拿它建閉包是安全的。
自己用 `var` ＋ `while` 手搖迴圈就會踩到——三個閉包指向同一格，跑完全變成終值。
這跟 C++ 在迴圈裡寫 `[&i]` 再把 lambda 存起來是**一模一樣的 bug**。

**解法**：用 `loop`／`seq`，或在圈內 `let` 一份出來（`(let [k j] (fn [] k))`）。

## 短函式 `|`

`|` 開頭是「短 lambda」，參數用 `$` 系列，寫 `map`／`filter` 時省很多字：

```janet
(map |(+ $ 1) [1 2 3])   # => @[2 3 4]     $  = 第一個參數
(|(+ $0 $1) 3 4)         # => 7            $0 $1 = 第 0、1 個
(map |$ [1 2])           # => @[1 2]       $ 自己就是恆等函式
```

⚠ **`|` 會吃掉後面那一個 form**，所以它常跟其他用途的 `|` 打架——
[25 序列工具](25-序列工具.md) 裡 `(interpose :| …)` 就是因為這個才不能寫。

## `defn-` 與文件字串

```janet
(defn- 內部用 [] :x)         # 加到 env 但標記 :private，import 時不會被帶出去
(defn 有文件 "這是說明" [x] x) # 參數表前面那個字串就是 docstring
```

`(get (dyn '內部用) :private)` 會是 `true`，公開的則是 `nil`。
docstring 在 REPL 用 `(doc 有文件)` 看得到（見 [07 REPL](07-repl.md)），
而且 Janet 會**自動把簽名接在最前面**：`(有文件 x)\n\n這是說明`。

模組門面只想公開幾個函式時，其餘一律 `defn-`——比事後維護一張匯出清單可靠。
