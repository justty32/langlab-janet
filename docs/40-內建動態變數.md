# 40 · 內建的動態變數（那一堆 `*星號*` 名字）

[12c dyn](12c-dyn.md) 講了**動態變數是什麼**（動態作用域，不是全域變數）。
這篇講 Janet **內建了哪些**，以及那個到處出現的 `*星號*` 命名到底是什麼東西。

## `*out*` 不是變數，它就是 keyword `:out`

這是理解一切的關鍵：

```janet
*out*              # => :out          ← 它求值出來就是一個 keyword
(dyn *out*)        # 等同 (dyn :out)
```

`*out*` 這個名字在 env 裡是一筆 `{:dyn true :value :out :doc "…"}` 的綁定。
所以**它不持有值，它只是那個 dyn 鍵的「有名字版本」**。

### 為什麼要多這一層：打錯名字會被擋下來

```janet
(dyn :ouy)     # => nil                       ⚠ 靜默，沒有人會告訴你打錯了
(dyn *ouy*)    # => compile error: unknown symbol *ouy*
```

裸 keyword 打錯只會安靜地回 `nil`，你會花很久才發現「為什麼設定沒生效」。
**星號版在編譯期就擋下來**（[34](34-讀錯誤訊息.md) 講的 compile error），
而且它帶 docstring，`(doc *out*)` 查得到。

> **慣例：自己的專案也該用 `defdyn` 定義星號名字，不要到處寫裸 keyword。**

## 三種用法

```janet
(dyn *out*)                      # 讀；沒設過回 nil
(dyn *out* :預設)                # 讀，沒設過就回這個預設值
(setdyn *out* buf)               # 設（影響目前 fiber 之後的程式碼）
(with-dyns [*out* buf] …)        # 設，離開區塊自動還原 ← 幾乎都用這個
```

實際用途最常見的一個：**把印出來的東西接進 buffer**。

```janet
(def b @"")
(with-dyns [*out* b] (print "這行去了 buffer"))
(string b)    # => "這行去了 buffer\n"
```

[23b](23b-用-spork-test-寫測試.md) 的 `capture-stdout`、[31](31-spork-產生-html.md) 的
`temple` 渲染，底下都是這一招。

## 內建的有哪些

### 輸出

| 名字 | 用途 |
|------|------|
| `*out*` | `print`／`printf` 印去哪 |
| `*err*` | `eprint` 之類的錯誤輸出印去哪 |
| `*pretty-format*` | `pp` 用的格式字串 |

### 這支程式的執行環境

| 名字 | 這台機器上實測到 |
|------|-----------------|
| `*args*` | `@["dv3.janet" "引數A" "引數B"]`——**第 0 格是腳本名**，跟 C 的 `argv` 一樣 |
| `*executable*` | `"janet"`——直譯器自己 |
| `*current-file*` | `"dv3.janet"`——**目前正在編譯的檔**，寫巨集或找相對路徑時有用 |
| `*syspath*` | `"/home/…/.local/lib/janet"`——系統模組裝在哪 |

⚠ `*args*` 是**原始的 argv**，不是解析過的。要解析旗標用
`spork/argparse`（[04 CLI 參數](04-cli-argparse.md)）。

### `import` 找不到檔時看這兩個

| 名字 | 用途 |
|------|------|
| `*module-paths*` | 覆寫 `module/paths`——**「could not find module」列出的候選路徑就是它算出來的** |
| `*module-cache*` | 覆寫 `module/cache`；同一支檔只會被載一次，重複 `import` 拿的是快取 |

`module/paths` 是 21 筆 `[路徑樣板 種類 檢查函式]`，其中的樣板長這樣：

```
:cur:/:all:.jimage        種類 :image
:cur:/:all:.janet         種類 :source
:cur:/:all:/init.janet    種類 :source
:cur:/:all::native:       種類 :native
```

⚠ 對照一下 [34 讀錯誤訊息](34-讀錯誤訊息.md) 裡那個 `could not find module` 的候選清單——
**它列的四行就是這四個樣板套進去的結果**。所以「找不到模組」不是玄學，
印一次 `module/paths` 就知道它去哪找過了（配合 [05e](05e-import-與模組路徑.md)）。

### 開發與 REPL

| 名字 | 用途 |
|------|------|
| `*debug*` | 開啟內建除錯器：出錯時停下來而不是直接跳掉 |
| `*redef*` | **允許重新定義頂層 `def`**。REPL 裡改一個函式再重載時需要它；⚠ 會讓產生的程式碼變慢，只在開發時開 |
| `*repl-prompt*` | 自訂 REPL 提示字元 |
| `*doc-width*` / `*doc-color*` | `(doc …)` 輸出的寬度與上色 |

### 結束流程

| 名字 | 用途 |
|------|------|
| `*exit*` | 設了就讓目前的 context 結束——`run-context` 會看它 |
| `*exit-value*` | 結束時 `run-context` 的回傳值 |

⚠ 這兩個**不是 `os/exit`**。`os/exit` 是直接砍掉整個行程；
這兩個是讓 REPL／`run-context` 這一層優雅收工（見 [12b 切換 env](12b-切換-env.md)）。

## 自己定義：`defdyn`

```janet
(defdyn *我的設定* "示範用：自訂的動態變數")

*我的設定*                       # => :我的設定
(dyn *我的設定*)                 # => nil        沒設過
(with-dyns [*我的設定* :開]
  (dyn *我的設定*))              # => :開
(dyn *我的設定* :預設)           # => :預設      沒設過時給預設
```

一行就換到「打錯會被編譯器擋下、`doc` 查得到」的待遇。
本 repo 的 `modules/llm-http` 用 dyn 當 logger 開關就是這個模式
（做法見 [28b spork/misc 文字與流程](28b-spork-misc-文字與流程.md)）。

⚠ 記得 dyn 是 **per-fiber** 的——開新 fiber 或執行緒時不會自動繼承，
細節見 [12c](12c-dyn.md) 與 [15 ev](15-ev-channel-net.md)。
