# 36 · 排序與比較

[21 數字與位元](21-數字與位元.md) 順帶提過三行排序。這篇講完整——包括一個
**會讓排序算出垃圾但不報錯**的寫法。

## 四個函式，兩兩一組

| 函式 | 就地改嗎 | 排序依據 |
|------|---------|---------|
| `sort` | ✓ 原地改，**同時回傳它自己** | 值本身，或你給的比較器 |
| `sorted` | ✘ 給你新的 array | 同上 |
| `sort-by` | ✓ 原地改 | **算出來的 key** |
| `sorted-by` | ✘ 給你新的 array | 同上 |

```janet
(def a @[3 1 2])
(sorted a)          # => @[1 2 3]   a 沒變
(sort a)            # => @[1 2 3]   a 變成 @[1 2 3]，回的就是 a 本身
(sorted-by |(- $) @[3 1 2])   # => @[3 2 1]   照 -x 排 = 降冪
```

這對得上 [25 序列工具](25-序列工具.md) 的規則三，但**注意例外**：那條規則說「驚嘆號＝原地改」，
`sort` 沒有驚嘆號卻是原地改的。**過去式（`sorted`）才是給你新的那個。**

## 比較器是「小於」，不是三路比較

自訂順序時傳第二個參數，它是**兩個參數、回真假**的函式——跟 C++ `std::sort` 的
`comp` 一樣，語意是「a 應該排在 b 前面嗎」：

```janet
(sorted @[3 1 2] <)   # => @[1 2 3]
(sorted @[3 1 2] >)   # => @[3 2 1]
```

### ⚠ 拿 `compare` 當比較器會算出垃圾，而且不報你真正的錯

Janet 有個 `compare`，但它回的是 **-1 / 0 / 1**：

```janet
(compare 1 2)   # => -1
(compare 2 2)   # =>  0
(compare 3 2)   # =>  1
```

C++ 的 `<=>`、Python 的舊 `cmp` 都長這樣，所以很容易順手傳進去。**結果是這個**：

```janet
(sorted @[3 1 2] compare)
# => error: expected integer key for array in range [0, 3), got 3
```

錯誤訊息在講陣列索引，完全看不出「你傳錯比較器了」。原因是
[32 那條規則](32-條件與模式比對.md)：**Janet 只有 `nil` 和 `false` 是假，`0` 是真**。
所以 `compare` 回的 `-1`、`0`、`1` **三個都是真**，排序演算法認為「永遠 a 在 b 前面」，
一路走出邊界。

> **要三路比較就用 `compare`，要排序就傳「小於」。兩者不能互換。**
> 另有現成的 `compare<`、`compare<=`、`compare=` 等，它們回真假，可以直接當比較器。

## 多鍵排序：兩種寫法

**`sorted-by` ＋ tuple key**（短，推薦）——因為 tuple 是**逐格比**的：

```janet
(< [1 2] [1 3])   # => true   第一格相同就比第二格
(< [1] [1 0])     # => true   短的排前面

(sorted-by |[($ :age) ($ :n)] 人)     # 先比 age，同 age 再比 n
```

**自訂比較器**（囉嗦，但條件複雜時才寫得出來）：

```janet
(defn 先age再n [x y]
  (if (= (x :age) (y :age))
    (< (x :n) (y :n))
    (< (x :age) (y :age))))
(sorted 人 先age再n)
```

兩者結果一樣。⚠ 但 `sorted-by` 每次比較都會**重算 key**——key 算起來貴的話
（例如要跑正則、要開檔）自己先算好存起來再排。

## ⚠ Janet 的排序**不穩定**

「穩定」＝鍵相同的元素保持原本的先後。Janet **不保證**：

```janet
(def xs (seq [i :range [0 8]] {:i i :k (mod i 2)}))
(map |($ :i) xs)                        # => @[0 1 2 3 4 5 6 7]
(map |($ :i) (sorted-by |($ :k) xs))    # => @[6 4 0 2 7 5 1 3]
```

`k = 0` 那組原本是 `0 2 4 6`，排完變成 `6 4 0 2`——**順序被打亂了**。

從 C++ 過來的人特別容易踩：`std::stable_sort` 是明確的一個函式，
Janet **沒有對應物**。要穩定就**把原始索引放進 key 的最後一格**：

```janet
(sorted-by |[($ :k) ($ :i)] xs)    # 用 :i 當最後的決勝鍵 → 結果可預測
```

## 跨型別排序不會報錯，但別依賴它

不同型別混在一起 `sorted` 是**合法的**，Janet 有一套內部的型別順序：

```janet
(sorted @[{} @[] :k "s" true nil 1 [] @""])
# => @[1 nil true "s" :k @[] () {} @""]
#     number nil boolean string keyword array tuple struct buffer
```

⚠ 這個順序**沒有寫進語言規格**，它只是實作細節。混型別的清單要排序，
自己給比較器把型別意圖講明白，不要靠這張暗表。

字串之間是**逐 byte 比**（ASCII），所以大寫排在小寫前面：

```janet
(sorted @["b" "A" "a"])   # => @["A" "a" "b"]
```

要不分大小寫就 `(sorted-by string/ascii-lower xs)`；中文則是比 UTF-8 的 byte，
**不是筆畫也不是注音**（見 [18 字串與 buffer](18-字串與-buffer.md)）。
