# 9-3c · 選哪套與會踩的坑

[上一篇](9-3b-測試配方與-spork-test.md)介紹了 spork/test。這篇收尾：兩套怎麼挑、中文訊息的小問題，以及寫測試時最常見的幾個坑。

## 中文訊息會變成一串 \xE4

spork/test 的失敗訊息是用 Janet 的表示法印的，非 ASCII 的字會被逃逸（換成 `\x..` 的編碼，2-2 講過）：

```janet
(import spork/test :as t)
(t/start-suite "zh")
(t/assert (= 1 2) "中文")
```

把這三行存成 `zh.janet`、最後補一行 `(t/end-suite)` 再跑，失敗那行長這樣：

```text
✘ zh.janet:3: "\xE4\xB8\xAD\xE6\x96\x87": false
```

訊息本身沒壞，只是看不懂。所以 spork/test 的訊息寫 ASCII 最省事，反正檔名與行號已經夠你定位。內建 `assert` 沒這個問題，它直接把字串當錯誤訊息丟出來，中文照常顯示。

## 該用哪一套

| 情況 | 用 |
|------|-----|
| 測試不多，不想多裝東西 | 內建 `assert` |
| 失敗訊息要寫中文 | 內建 `assert` |
| 一支檔很多條，想一次看到全部失敗 | spork/test |
| 要檢查「該爆／不該爆」、要抓 `print` 的輸出 | spork/test |

兩套可以混用。spork/test 沒有接管任何東西，同一支檔裡照樣能寫內建 `assert`；`jpm test` 兩種都只看 exit code。

## 你會踩的坑

⚠ 省掉 assert 的訊息

你會以為：`(assert (= x 3))` 失敗時 Janet 會告訴我哪裡錯。

其實是：你只拿到 `assert failure in (= x 3)`，看不出 `x` 是什麼、這條在保護什麼。

因為：沒給訊息時，`assert` 只能把程式碼原樣印出來。它不知道你的意圖，只有你寫的那句「應該怎樣」知道。

⚠ 用 `=` 比 array

你會以為：`(assert (= (get-list) @[1 2]) "…")` 在內容一樣時會過。

其實是：永遠失敗，內容一樣也一樣。

因為：`=` 對 array、table 比的是「是不是同一個東西」。函式回傳的 array 和你手寫的 `@[1 2]` 是兩個東西。改用 `deep=`。

⚠ 永遠不會紅的「該失敗」測試

你會以為：想測「平均值遇到 0 筆資料會丟錯」，寫了 `(def [ok e] (protect (/ total n)))`，再用 `(unless ok (assert …))` 檢查錯誤訊息。跑起來是綠的，放心了。

其實是：`ok` 一直是 `true`，`unless` 裡那條 `assert` 從來沒執行過。這條測試永遠不會紅，什麼都沒保護到。

因為：Janet 的 `(/ 1 0)` 得到 `inf`，`(get nil :a)` 得到 `nil`，都不是錯誤。所以一定先寫 `(assert (not ok) …)` 確認真的爆了，而且動筆前先在 REPL 試一次。

⚠ 共用工具檔被當成測試跑

你會以為：`test/helpers.janet` 只是給別的測試 import 的，`jpm test` 會略過它。

其實是：它也會被跑一次，而且排在字母順序那個位置。裡面最外層有 `print` 或會出錯的程式碼，就會多出一段輸出甚至一個失敗。

因為：`jpm test` 不分辨誰是測試、誰是工具，`test/` 底下看到 `.janet` 就跑。工具檔只放定義。

⚠ 拿 skip-asserts 當「暫時跳過」

你會以為：`(t/skip-asserts 1)` 像別家框架的 `skip`，下一條先不算，整體照樣是綠的。

其實是：整個 suite 變紅。實測跳過一條本來會過的，另一條正常：

```text
test suite skip finished in 0.000 seconds - 1 of 2 tests passed.
```

行程以 exit code 1 結束。

因為：被跳過的那條算進「跑了幾條」，但永遠不算進「過了幾條」。要暫停某幾條就把它註解掉，或搬到別支檔。
