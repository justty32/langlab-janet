# 10-2 · ev 非同步：一條執行緒輪流跑很多件事

上一課的 fiber 是「可以暫停的函式」。這課教 ev（Janet 內建的排程器，負責在很多個 fiber 之間輪流切換）。學完你能同時等好幾件慢事（睡覺、讀網路、等檔案），而且程式碼寫起來跟一行一行的同步程式一模一樣。

## 這是什麼、為什麼

程式最常在「等」：等網路回應、等檔案讀完、等一秒過去。等的時候 CPU 其實閒著。傳統解法有兩種：開很多執行緒（貴、要鎖），或者用 callback／async-await（程式碼被切成碎片）。

Janet 的做法：只有一條執行緒，但把每件事包成 fiber。某個 fiber 開始等（睡、讀網路）的瞬間，它自動 `yield` 讓出來，排程器就換下一個 fiber 跑。等的東西好了，排程器再把它 `resume` 回來。這個排程器就是 ev（event loop 的縮寫，事件迴圈）。

對你來說，程式碼就是一行接一行寫，沒有 callback、沒有 `await` 關鍵字。切換是在等待點自動發生的。比喻是一個人同時煮三鍋湯：哪鍋要等就先去看別鍋。比喻不準的地方是這個人切換得極快，而且只有在「等」的時候才切，不會在你切菜切到一半時把刀搶走。

三個東西：`ev/spawn` 丟一件事到背景、`ev/sleep` 讓出來睡一下、`ev/chan`（channel，fiber 之間傳值的管子）。

## 動手：spawn 與 sleep

```janet
(ev/spawn (print "背景 A"))
(ev/spawn (print "背景 B"))
(print "主線先印")
(ev/sleep 0)
(print "主線 sleep 完")
# 印出：主線先印 / 背景 A / 背景 B / 主線 sleep 完
```

`ev/spawn` 只是把工作排進去，不會馬上跑，所以「主線先印」先出來。主線 `(ev/sleep 0)` 的意思是「我讓出來一下，睡零秒」，排程器趁這個空檔把 A、B 跑完，再回到主線。

交錯的效果用兩個不同速度的迴圈最清楚：

```janet
(ev/spawn (for i 0 3 (print "慢 " i) (ev/sleep 0.02)))
(ev/spawn (for i 0 3 (print "快 " i) (ev/sleep 0.01)))
(ev/sleep 0.1)
# 印出：慢 0 / 快 0 / 快 1 / 慢 1 / 快 2 / 慢 2
```

兩個迴圈各自寫得像同步程式，但輸出是交錯的，因為每次 `ev/sleep` 都是切換點。主線最後那個 `(ev/sleep 0.1)` 是等他們做完，不然主線先結束程式就退出了。

## 動手：channel 傳值

背景做完的結果要怎麼交回來？用 channel：

```janet
(def ch (ev/chan))
(ev/spawn (ev/sleep 0.02) (ev/give ch "worker done"))
(print "主線等結果")
(ev/take ch)   # => "worker done"
```

`ev/give` 把值放進管子，`ev/take` 從管子拿。管子空的時候 `take` 會停在那裡等（不是卡住整個程式，是這個 fiber 讓出去等），有東西進來才回來。這就是「等一件背景的事做完」最直接的寫法。

多個工人各做各的，主線收幾個就等幾個：

```janet
(def results (ev/chan 10))
(for i 0 3 (ev/spawn (ev/sleep (* 0.01 (- 3 i))) (ev/give results i)))
(seq [_ :range [0 3]] (ev/take results))   # => @[2 1 0]
```

`(ev/chan 10)` 是容量 10 的管子，放滿了 `give` 才會等；`(ev/chan)` 不帶數字是容量 0，`give` 一定要等到有人 `take` 才回來。這裡工人 2 睡最短所以最先交，順序是完成順序。

只想「一堆事全部做完再說」有現成的 `ev/gather`，結果照你寫的順序排：

```janet
(ev/gather (do (ev/sleep 0.02) :a) (do (ev/sleep 0.01) :b))   # => @[:a :b]
```

## 動手：逾時與取消

```janet
(protect (ev/with-deadline 0.02 (ev/sleep 10)))   # => (false "deadline expired")
```

`ev/with-deadline` 給 body 一個時限，超過就丟錯，用 `try`／`protect` 接。取消一個背景工作用 `ev/cancel`，對方會在下一個等待點收到一個例外：

```janet
(def task (ev/go (fn [] (try (forever (ev/sleep 0.01)) ([e] (print "被取消了：" e))))))
(ev/sleep 0.03)
(ev/cancel task "夠了")
(ev/sleep 0.03)
# 印出：被取消了：夠了
```

`ev/go` 跟 `ev/spawn` 一樣，差別是它吃函式、回傳那個 fiber，你才有東西可以 `cancel`。

## 你會踩的坑

⚠ 你會以為背景 fiber 會「自己」跑起來，主線寫個 `(while true ...)` 忙迴圈也沒關係。其實是背景一步都動不了，程式卡死。因為只有一條執行緒，切換只在 `ev/sleep`、channel、網路讀寫這些等待點發生；純算數的迴圈沒有等待點，排程器永遠拿不回控制權。實測 `timeout 2 janet -e '(ev/spawn (print "背景")) (while true)'` 兩秒後被砍掉，「背景」一次都沒印。要讓出來就在迴圈裡放 `(ev/sleep 0)`。

⚠ 你會以為程式主線跑完就結束。其實是還有排在 ev 上的計時器就會等它。因為 `(ev/go (fn [] (ev/sleep 99)))` 掛上去後，排程器要等所有事做完才肯退出。長睡的工作用完記得 `ev/cancel`。

⚠ 你會以為 `ev/chan-close` 之後管子裡剩的東西還拿得到（Go 是這樣）。其實是 `take` 直接回 `nil`，裡面的東西丟了。因為 Janet 的 close 是「整條管子作廢」。要通知「沒了」，就送一個約定好的結束值，例如 `:done`，收的人看到就停。
