# 3-3 · 相等與比較

「這兩個東西一樣嗎」聽起來是最簡單的問題，但在 Janet 它有兩種答案，看你問的是哪一種容器。這課講清楚 `=` 到底在比什麼、什麼時候要改用 `deep=`，以及為什麼拿 array 當字典的鍵會讓你找不到東西。

## 這是什麼、為什麼

「一樣」有兩種意思。一種是「內容一不一樣」：兩張紙上寫的字相同。另一種是「是不是同一個」：根本就是同一張紙（術語叫身分，identity）。Python 的 `==` 和 `is`、JS 的 `==` 和物件比較，都在區分這兩件事。

Janet 的規則綁在 3-1 那條「可變 vs 不可變」上：

| 型別 | `=` 比什麼 |
|------|-----------|
| 數字、字串、keyword、nil、true／false | 內容 |
| tuple、struct（不可變） | 內容 |
| array、table（可變） | 是不是同一個 |

為什麼可變的要比身分？因為可變的東西內容隨時會變，「現在內容一樣」下一秒可能就不一樣了，所以 Janet 選擇只在「同一個」時才說相等。不可變的東西內容定了就不會變，比內容才有意義。這個規則影響到 `=`、`case`、`index-of`、字典的鍵，一次搞懂省很多事。

## 動手

### 基本型別比內容

```janet
(= 1 1)       # => true
(= 1 1.0)     # => true
(= "ab" (string "a" "b"))   # => true
(= :a :a)     # => true
(= nil nil)   # => true
(= "1" 1)     # => false
```

數字、字串、keyword 都是比內容。最後一行要注意：Janet 不會偷偷把 `"1"` 轉成 `1`，不同型別一律不相等，這點跟 JS 的 `==` 相反。

### tuple、struct 比內容

```janet
(= [1 2] [1 2])         # => true
(= {:a 1} {:a 1})       # => true
(= [1 [2 3]] [1 [2 3]])   # => true
```

兩個分開寫出來的 tuple，內容一樣就相等，巢狀的也一路比進去。這是你直覺上想要的行為。

### array、table 比「是不是同一個」

```janet
(= @[1 2] @[1 2])       # => false
(= @{:a 1} @{:a 1})     # => false
(def a @[1 2])
(def b a)
(= a b)                 # => true
```

前兩行看起來很怪：內容明明一樣，卻說不相等。因為 `@[1 2]` 寫兩次就是做了兩個 array，`=` 問的是「同一個嗎」，答案是不。`(def b a)` 沒有複製，只是幫同一個 array 多取一個名字，所以 `a` 和 `b` 是同一個，`=` 才說 true。

### 要比內容用 `deep=`

```janet
(deep= @[1 2] @[1 2])       # => true
(deep= @{:a @[1 2]} @{:a @[1 2]})   # => true
(deep= [1 2] @[1 2])        # => false
```

`deep=` 不管可變不可變，從外到內一層一層比內容。但第三行提醒你：型別也要一樣，tuple 跟 array 內容相同仍然不相等。要「內容一樣就好」的時候，`deep=` 就是你要的；反過來的 `deep-not=` 也有。

### 拿容器當字典的鍵

```janet
(def 棋盤 @{})
(put 棋盤 [0 0] :king)
(put 棋盤 [7 7] :rook)
(get 棋盤 [7 7])   # => :rook
(length 棋盤)      # => 2
```

座標、成對的名字這類「組合起來的鍵」，用 tuple 當鍵很自然。因為 tuple 比內容，你事後寫一個新的 `[7 7]` 去查，查得到。

```janet
(def 壞棋盤 @{})
(put 壞棋盤 @[0 0] :king)
(get 壞棋盤 @[0 0])   # => nil
(length 壞棋盤)       # => 1
```

換成 array 當鍵，東西放得進去（長度是 1），但你用另一個新的 `@[0 0]` 去查，是 `nil`。因為 table 找鍵也是用 `=`，兩個 array 不是同一個，就找不到。只有拿當初那個 array 本身去查才找得到，實務上幾乎沒有用。

要拿可變的當鍵，先把它變不可變：`(freeze @[0 0])` 會回 `(0 0)`，也就是一個 tuple。`freeze` 是從外到內整包轉成不可變版本，docs/35 講得細。

### 大小比較：`<` 和 `compare`

```janet
(< 1 2)             # => true
(< "a" "b")         # => true
(< [1 2] [1 3])     # => true
(compare 1 2)       # => -1
(compare [1 2] [1 2])   # => 0
(sort @[[2 1] [1 9] [1 2]])   # => @[(1 2) (1 9) (2 1)]
```

`<`、`>` 這些不只吃數字，字串和 tuple 也行，tuple 是逐格比，第一格相同就看第二格。`compare` 回三種值：小於是 `-1`、相等是 `0`、大於是 `1`。所以 tuple 可以直接丟給 `sort` 排序，多欄位排序就是把欄位排進 tuple 裡。

## 你會踩的坑

⚠ 你會以為 `(= 計算出來的array 預期的array)` 可以拿來檢查結果。其實它永遠是 false，因為兩邊是不同的 array。寫測試（9-3）或 `assert` 時比 array／table，一律用 `deep=`。

⚠ 你會以為 tuple 比內容，所以 `(= [1 @[2 3]] [1 @[2 3]])` 也是 true。其實是 false。因為外層 tuple 逐格比的時候，第二格是兩個不同的 array，那一格就用 `=` 的規則（比身分）判定不相等。要整包比內容還是 `deep=`。

⚠ 你會以為 `(index-of @[1 2] 清單)` 可以在清單裡找到內容一樣的那個 array。其實找不到，回 `nil`。因為 `index-of` 是用 `=` 逐個比。清單裡放 tuple 就找得到：`(index-of [1 2] @[[1 2] [3 4]])` 回 `0`。

## 小練習

1. 寫一個 `@{}`，用 `[x y]` 座標當鍵放三個東西，再用新寫的座標把它們全部取出來。
2. 分別用 `=` 和 `deep=` 比 `@{:a @[1]}` 和 `@{:a @[1]}`，印出兩個結果並確認你能解釋為什麼不同。
3. 用 `sort` 把 `@[["Bob" 30] ["Ann" 30] ["Cid" 25]]` 排好，觀察它先比名字還是先比年齡；再把每一格反過來放成 `[年齡 名字]` 排一次。
