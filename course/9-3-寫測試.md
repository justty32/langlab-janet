# 9-3 · 寫測試

9-2 講過用 `jpm test` 跑測試，這課教你怎麼寫。學完你會寫最基本的測試、看得懂 `jpm test` 的成功與失敗輸出，也知道它到底怎麼找到你的測試檔。

## 這是什麼、為什麼

測試就是「一段幫你檢查程式有沒有照預期動作的程式」。改了程式碼之後跑一下，壞了馬上知道，不用自己一個一個手動試。

你可能用過 Python 的 pytest、JS 的 Jest，它們有 `describe`、`it`、`@Test` 這類東西要學。Janet 沒有這些。在 Janet 裡，一支測試就是一支普通的 `.janet` 程式，規則只有一條：

- 從頭跑到尾沒出事，就是通過。
- 中途丟出錯誤（error，程式跑到一半喊停），讓行程以非 0 的 exit code 結束，就是失敗。

exit code 是程式結束時交給作業系統的數字，0 代表沒事，其他數字代表出事。C 的 `return 1`、Python 的 `sys.exit(1)` 就是在設它。所以你已經會寫 Janet 測試了，剩下的只是慣例。

## 動手

這課的程式都在 `examples/course/9-3.janet`，示範專案是 9-2 那個 `examples/course/9-demo/`。

### 最小的測試：assert

`assert` 吃兩個參數：一個條件、一段訊息。條件成立就沒事，不成立就丟錯，錯誤訊息就是你給的那段字。

```janet
(assert (= (+ 2 2) 4) "2 + 2 should be 4")
```

條件成立，所以什麼事都沒發生。把它改成會失敗的樣子，用 `protect`（7-1 教過，把錯誤接住，變成 `[成功與否 值]` 兩格）看看錯誤訊息：

```janet
(protect (assert (= 1 2) "month should be 0-based"))   # => (false "month should be 0-based")
(protect (assert (= 1 2)))   # => (false "assert failure in (= 1 2)")
```

第二行省掉訊息，Janet 只能告訴你「`(= 1 2)` 不成立」，不會告訴你這代表什麼事壞了。訊息請一定要寫，而且寫「應該怎樣」。

`assert` 成功時回傳的是被檢查的那個值本身，不是 `true`：

```janet
(assert 5 "x")   # => 5
(assert (+ 1 2) "sum")   # => 3
```

所以可以一邊檢查一邊拿來用，例如 `(def cfg (assert (load-config) "設定檔載不進來"))`。

訊息要把數字塞進去時用 `assertf`，寫法跟 `string/format` 一樣：

```janet
(protect (assertf (= 1 2) "want %d got %d" 1 2))   # => (false "want 1 got 2")
```

### 示範專案裡的測試檔

`examples/course/9-demo/test/basic.janet` 就是一支用內建 `assert` 寫的測試：

```janet
(import ../demo/init :as demo)

(assert (= (demo/add 1 2) 3) "1 + 2 應該是 3")
(assert (= (demo/greet) "Hello, world!") "沒給名字要用 world")
(assert (= (demo/greet "Janet") "Hello, Janet!") "有給名字要用名字")
(assert (= (demo/count-words "a b  c") 3) "連續空白不算一個字")

(print "basic 測試通過")
```

最後那行 `print` 是慣例：`jpm test` 成功時很安靜，印一行才確定它真的跑到底。

### jpm test 怎麼找測試檔

```sh
cd examples/course/9-demo
jpm test
```

```text
generating executable c source build/demo.c from bin/main.janet...
compiling build/demo.c to build/build___demo.o...
linking build/demo...
running test/basic.janet ...
basic 測試通過
running test/with-spork.janet ...
test suite demo finished in 0.000 seconds - 5 of 5 tests passed.
✓ All tests passed.
```

前三行是 `jpm test` 先幫你 build 一次（這個專案有宣告執行檔，細節見 9-2），跑完記得 `jpm clean` 清掉 `build/`。

後面才是測試。`jpm test` 做的事很單純：把 `test/` 底下每一支 `.janet` 依檔名排序，每支各開一個新的 janet 行程去跑，看它的 exit code。沒有註冊、沒有設定檔。

「每支各開一個行程」帶來三個後果：

1. 測試之間不共享狀態。A 檔改了什麼，B 檔看不到。
2. 每支檔都要自己 `import` 要測的東西，像上面第一行那樣。
3. 你放在 `test/` 裡的共用工具檔也會被當成一支測試跑。所以工具檔只能放 `defn`、`def` 這類定義，不能在最外層印東西或做事。

### 失敗長什麼樣

我們把整個 `9-demo` 複製到別處，加一支故意寫錯的 `test/b-bad.janet`：

```janet
(import ../demo/init :as demo)

(assert (= (demo/add 1 2) 4) "1 + 2 應該是 4（故意寫錯）")
(print "b-bad 這行印得出來嗎？")
```

```text
（前三行 build 訊息省略）
running test/b-bad.janet ...
error: 1 + 2 應該是 4（故意寫錯）
  in thunk [test/b-bad.janet] (tail call) on line 3, column 1
non-zero exit code in test/b-bad.janet: 1
running test/basic.janet ...
basic 測試通過
running test/with-spork.janet ...
test suite demo finished in 0.000 seconds - 5 of 5 tests passed.
✘ Failing test scripts: 1
```

從這段輸出可以讀出四件事：

1. 錯誤訊息就是你寫的那句，下一行告訴你檔名 `test/b-bad.janet` 與行號 `line 3`。
2. 一支失敗不會擋住後面的，`basic`、`with-spork` 照跑。
3. 同一支檔裡，失敗那行之後就不跑了：`b-bad 這行印得出來嗎？` 沒印出來。
4. 最後 `jpm test` 自己以 exit code 1 結束，CI（自動跑測試的伺服器）就靠這個判斷紅燈。

第 3 點是內建 `assert` 最惱人的地方：第一條壞掉會遮住後面的問題。續篇的 spork/test 會解決它。
