# 11-5 · 接下來去哪

這是最後一課，不教新語法。前半把十一個單元攤開看一遍，對一下 todo 用到了哪些；後半告訴你這個 repo 其他五個區各是什麼、什麼時候該去。

## 這是什麼、為什麼

課程是照順序讀的，一次只講一件事。真的寫東西時你不會照順序來，你會卡在某個點上：忘了某個函式叫什麼、撞到一個說不通的行為、想要一段現成的程式碼。這時候要的是「查」，不是「上課」。

這個 repo 本來就有一大堆查資料用的東西，只是它們寫得很密，假設你已經懂 Lisp。現在你懂了，可以去用了。這課就是一張地圖。

## 動手：todo 用到了哪些

`examples/course/11-todo/` 的程式本體（不算測試）不到兩百行，卻把前面好幾個單元都用上了。單元 1、2、5、6 的東西到處都是，就不列了；下面是比較好指認的幾樣：

| todo 裡的東西 | 在哪 | 學自 |
|---------------|------|------|
| 空資料長 `@{:next-id 1 :items @[]}`，一張 table 裡放一個 array | `store/empty-db` | 單元 3 |
| 存檔用 `json/encode`，讀檔用 `json/decode` | `store/save`、`store/load` | [4-3](4-3-JSON.md) |
| `slurp` 讀、`spit` 寫、`os/stat` 看檔案在不在 | `store/load` | [8-1](8-1-讀寫檔案.md)、[8-2](8-2-目錄與路徑.md) |
| 壞掉的 JSON 用 `protect` 接住，再 `errorf` 丟一句人看得懂的話 | `store/load` | [7-1](7-1-錯誤怎麼丟怎麼接.md) |
| 每個子命令各跑一次 `argparse`，自動有 `--help` | `todo/cli.janet` | [8-3](8-3-命令列參數.md) |
| `(import ./todo/cli)`，資料層和指令層分兩個檔 | `main.janet` | [9-1](9-1-import-與拆檔.md) |
| `test/` 底下兩支測試，`jpm test` 一次跑完 | `test/` | [9-3](9-3-寫測試.md) |
| `project.janet` 宣告執行檔，`jpm build` 編成一支 | `project.janet` | [9-2](9-2-jpm-專案.md) |

單元 10 沒用上，因為 todo 不需要同時做兩件事、也不需要解析複雜的文字。等你的程式需要時再回去翻。

## 動手：數一數每一區有多少東西

範例檔用 8-2 學的 `os/stat` 與 `os/dir` 把五個區各數一次。它讀的是相對路徑，所以要站在 repo 根目錄跑：

```sh
cd janet-lab
janet examples/course/11-5.janet
# == 數一數每區有幾支檔 ==
# docs/         96 支 .md
# reference/    24 支 .md
# cheatsheets/  9 支 .md
# snippets/     20 支 .janet
# exercises/    6 支 .janet
```

站錯地方跑，`os/stat` 會回 `nil`，範例檔就印「找不到（要從 repo 根目錄跑）」，不會炸。這是 8-2 那招：先問檔案在不在，再去讀。

五個區各是什麼、該什麼時候去，在續篇：[11-5b · 五個區怎麼用](11-5b-五個區怎麼用.md)
