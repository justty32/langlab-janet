# 7-1 · 錯誤怎麼丟、怎麼接

程式跑到一半碰到做不下去的事：檔案不在、資料格式壞掉、算出來的東西不合理。這課教你怎麼在 Janet 裡「喊停」（丟錯誤），怎麼在外層「接住」繼續跑，以及什麼時候該喊停、什麼時候安靜回 `nil` 就好。

## 這是什麼、為什麼

你在別的語言用過 `throw`／`raise` 跟 `try`／`catch`。Janet 的做法一樣，只是名字不同：`error` 負責丟，`try` 負責接。

最大的差別是：Janet **沒有「例外類別」這種東西**。`error` 丟出去的就是一個普通的值，字串也行，數字也行，一個 table（可變的字典）也行。接的人拿到的就是你丟的那個值，原封不動。所以你不用先定義一整棵 exception class 才能開始丟錯，想帶欄位就丟一個 table。

## 動手

### 丟出去：error

`error` 拿一個值，馬上中斷目前在跑的東西，把那個值往外丟。沒人接的話，整支程式停下來，終端機會印出這樣：

```
error: boom
  in thunk [demo.janet] (tail call) on line 1, column 1
```

第一行是你丟的值，下面幾行是「炸在哪裡」，7-3 會逐行講。

### 接住：try

`try` 的形狀是「先寫要試的東西，再寫一段 `([e] ...)` 說接到之後怎麼辦」。`e` 就是被丟出來的那個值，名字你自己取。

```janet
(try
  (error "boom")
  ([e] (string "接到了 " e)))
# 回傳 "接到了 boom"
```

沒炸的話，`try` 回的就是 body 自己的值，catch 那段不會跑：

```janet
(try (+ 1 2) ([e] :caught))   # => 3
```

⚠ `([e] ...)` 長得像在呼叫一個函式，其實不是。它是 `try` 自己的寫法：方括號放接到的錯誤要叫什麼名字，後面放接到之後要做的事。

### 不想寫 try：protect

有時候你只想知道「成功了嗎」。`protect` 把一段程式包起來，回一個兩格的 tuple（一串放進去就不能改的值）：第一格是成功與否，第二格是結果或錯誤。

```janet
(protect (+ 1 2))          # => (true 3)
(protect (error "bad"))    # => (false "bad")
```

拿來配解構（把 tuple 直接拆成兩個名字）很順：

```janet
(def [ok v] (protect (error "bad")))
ok   # => false
v    # => "bad"
```

### 帶格式的錯誤訊息：errorf

`errorf` 就是先用 `string/format` 組字串再 `error`，`%s` 放字串、`%d` 放整數、`%j` 放任何值：

```janet
(protect (errorf "file %s missing (code %d)" "a.txt" 2))
# => (false "file a.txt missing (code 2)")
```

### 卡住前提：assert

`assert` 檢查一個條件，是假的（`nil` 或 `false`）就丟錯，是真的就把那個值回給你。第二個參數是錯誤訊息，可以不給：

```janet
(protect (assert (= 1 2) "should be equal"))   # => (false "should be equal")
(protect (assert (= 1 2)))   # => (false "assert failure in (= 1 2)")
(assert 5 "never shown")     # => 5
```

Janet 的 `assert` 不會像 C 那樣被編譯選項關掉，它就是一般的執行期檢查。在函式開頭用它擋掉壞資料，錯誤就會在進門口炸，而不是三層之外。

### 錯誤可以是任何值：丟 table 就能帶欄位

字串只能講一句話。需要帶錯誤碼、路徑之類的資料時，直接丟 struct（不可變的字典）或 table，接的人用鍵取欄位：

```janet
(try
  (error {:code 404 :path "/users/9"})
  ([e] (e :code)))   # => 404
```

`(e :code)` 是「拿 e 裡面 :code 那格」，3-2 教過的寫法。
