# 10-5 · 原型與方法：Janet 的物件就這麼多

從 Python／JS 過來你會找 `class`。Janet 沒有，但有兩個小機制拼起來就夠用：方法呼叫語法 `(:speak dog)`，跟原型（prototype，一張「自己查不到 key 時去問」的備用 table）。這課教這兩個，順便拆掉一個最常見的坑。

## 這是什麼、為什麼

你在 8-1 已經寫過 `(:read f :line)`、`(:close f)`，那就是方法呼叫。它其實沒有魔法：把 keyword 放在呼叫位置，Janet 就去物件裡查那個 key 的值（應該是個函式），然後把物件自己當第一個參數傳進去。

原型解決的是「一百隻狗要共用同一個 `speak` 函式」。每隻狗的 table 只放自己的資料，把 `speak` 放在一張共用的 table 上，狗的 table 指向它。查 key 的時候自己沒有就去那張表找。這張表就是原型，扮演的是別的語言裡「類別」的角色。

先講結論：大部分時候你不需要原型。Janet 的預設風格是「純資料 table 加普通函式」。只有一群函式共用同一份狀態、又需要「同名方法、不同實作」時才搬出來。

## 動手：方法呼叫語法

```janet
(def dog @{:name "Rex" :speak (fn [self] (string (self :name) " woof"))})
(:speak dog)   # => "Rex woof"
((get dog :speak) dog)   # => "Rex woof"
```

兩行等價：`(:speak dog)` 就是「取出 `:speak`，把 `dog` 當第一個參數叫它」。`self` 沒有特殊地位，是普通參數，你想叫 `this` 也行。要傳更多參數就接在後面：`(:speak dog "loud")` 會呼叫 `(f dog "loud")`。

## 動手：原型

```janet
(def Animal @{:speak (fn [self] (string (self :name) " makes a sound"))
              :intro (fn [self] (string "I am " (self :name)))})
(defn animal [name] (table/setproto @{:name name} Animal))
(def cat (animal "Tom"))
(:intro cat)   # => "I am Tom"
(:speak cat)   # => "Tom makes a sound"
(keys cat)   # => @[:name]
(type (get cat :speak))   # => :function
(table/rawget cat :speak)   # => nil
```

`Animal` 只是一張放函式的 table，用大寫開頭純粹是習慣。`table/setproto` 把 `cat` 的原型設成 `Animal` 並回傳 `cat`。`(:intro cat)` 查 `:intro` 時 `cat` 自己沒有，往原型找到了。`keys` 只列自己的，所以看不到方法；`get` 會走原型鏈；`table/rawget` 只看自己這層。

繼承就是原型再掛原型：

```janet
(def Animal @{:speak (fn [self] (string (self :name) " makes a sound"))
              :intro (fn [self] (string "I am " (self :name)))})
(def Dog (table/setproto @{:speak (fn [self] (string (self :name) " woof"))} Animal))
(def d (table/setproto @{:name "Rex"} Dog))
(:speak d)   # => "Rex woof"
(:intro d)   # => "I am Rex"
```

查找順序 `d` → `Dog` → `Animal`，先找到先贏。`Dog` 蓋掉了 `speak`，`intro` 沒定義就一路往上拿到 `Animal` 的。沒有 `super` 關鍵字；要叫上一層的版本就自己 `(table/getproto Dog)` 去拿。

方法要改自己的狀態就直接 `put` 到 `self` 上：

```janet
(def counter @{:n 0 :bump (fn [self] (put self :n (+ (self :n) 1)) (self :n))})
(:bump counter)   # => 1
(:bump counter)   # => 2
```

## 動手：有 :close 就能配 with

7-2 學過的 `with` 結束時會呼叫 `:close`。所以你的物件只要有 `:close` 方法，就自動享受「拋錯也會收尾」：

```janet
(def Conn @{:close (fn [self] (print "closed"))
            :query (fn [self q] (string "ran " q))})
(defn connect [] (table/setproto @{:host "x"} Conn))
(with [c (connect)] (:query c "select 1"))   # => "ran select 1"
# 印出：closed
(try (with [c (connect)] (error "boom")) ([e] (string "caught " e)))   # => "caught boom"
# 印出：closed
```

## 你會踩的坑

⚠ 你會以為 `(:port cfg)` 是「取出 `cfg` 的 `:port`」（Clojure 是這樣）。其實是回 `nil`，而且不報錯。因為它是方法呼叫，展開成 `((get cfg :port) cfg)`，也就是 `(4000 cfg)`。數字放在呼叫位置代表「用 4000 當索引去查 cfg」，查不到就 `nil`，整條鏈沒有一步會出錯，這個 bug 會安靜流到很遠的地方。記法：`(集合 鍵)` 取值，`(:鍵 物件)` 呼叫方法。

```janet
(def cfg {:port 4000})
(cfg :port)   # => 4000
(:port cfg)   # => nil
(4000 cfg)   # => nil
```

⚠ 你會以為方法的參數就是你呼叫時寫的那幾個。其實是前面多一個 `self`。因為 `(:inc obj 5)` 實際呼叫 `(f obj 5)`，寫成 `(fn [n] ...)` 就炸 `called with 2 arguments, expected 1`。方法的第一個參數永遠留給自己。

⚠ 你會以為原型上放 `@{:items @[]}` 當預設值，每個物件會各拿一份。其實是所有物件共用同一個 array。因為原型是共用的，`(a1 :items)` 跟 `(a2 :items)` 是同一個東西，往一個推東西另一個也看得到。可變的預設值要在建構函式裡各給各的：`(table/setproto @{:items @[]} Proto)`。
