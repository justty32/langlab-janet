# 8-1b · 讀寫檔案（一行一行讀）

接續 [8-1](8-1-讀寫檔案.md)。`slurp` 一次把整個檔吞進記憶體，檔案很大時不划算；
這篇教你先打開檔案，再一行一行讀、分好幾次寫。

## 這是什麼、為什麼

`(file/open 路徑 模式)` 打開檔案，回一個 file handle。之後讀寫都對著它做，
做完要關掉（`file/close`），不然作業系統那邊的資源一直占著。

問題是「記得關」很容易忘，程式中途出錯更會跳過關檔那行。
所以打開檔案一律搭 `with`：它在區塊結束時自動幫你關，出錯跳出去也照樣關。
用書比喻，`with` 就像借書時綁了一條規則「離開房間就自動還書」。
比喻不準的地方是：真正發生的事是區塊結束時呼叫一次 `(:close f)`，沒有別的魔法。

## 動手：寫檔和模式字串

```janet
(def tmp (string (or (os/getenv "TMPDIR") "/tmp") "/janet-course-8-1"))
(os/mkdir tmp)
(def p (string tmp "/fruits.txt"))
(with [f (file/open p :w)]
  (file/write f "apple\n")
  (:write f "banana\n" "cherry\n"))
(slurp p)   # => @"apple\nbanana\ncherry\n"
(os/rm p)
(os/rm tmp)
```

`with [f (file/open p :w)]` 的意思是：打開檔案、把 handle 取名 `f`，區塊結束就關掉。

`(file/write f ...)` 和 `(:write f ...)` 做的事完全一樣。後者是「方法呼叫」寫法：
把 `:write` 放最前面，Janet 會去找 `f` 身上叫 write 的功能來用。挑一種順手的就好。
兩者都可以一次給好幾段文字。

第二個參數 `:w` 是模式，告訴系統你打算怎麼用這個檔：

| 模式 | 意思 |
|------|------|
| `:r` | 讀（預設，不寫就是它）。檔案要已經存在 |
| `:w` | 寫。檔案不在就建，在的話先清空 |
| `:a` | 附加，寫的東西接在檔尾 |
| 加 `b` | 二進位模式，例 `:rb` `:wb` `:ab`，不翻譯換行 |
| 加 `+` | 同時可讀可寫，例 `:r+` `:a+` |

## 動手：一行一行讀

```janet
(def tmp (string (or (os/getenv "TMPDIR") "/tmp") "/janet-course-8-1"))
(os/mkdir tmp)
(def p (string tmp "/lines.txt"))
(spit p "one\ntwo\n")
(with [f (file/open p :r)]
  (while (def line (file/read f :line))
    (prin "讀到：" line)))
# 印出：
# 讀到：one
# 讀到：two
(os/rm p)
(os/rm tmp)
```

`(file/read f :line)` 每呼叫一次讀一行，回的是 buffer，而且換行字元 `\n` 還留在尾巴，
所以這裡用 `prin`（印完不換行）才不會多空一行。讀到檔尾沒東西了回 `nil`。

`(while (def line ...) ...)` 利用這點：`def` 的結果就是 `line` 的值，
是 `nil` 時 `while` 就停，迴圈自然結束。

除了 `:line`，第二個參數還能給 `:all`（剩下的全部讀完）或一個數字（最多讀這麼多 bytes）：

```janet
(def tmp (string (or (os/getenv "TMPDIR") "/tmp") "/janet-course-8-1"))
(os/mkdir tmp)
(def p (string tmp "/abc.txt"))
(spit p "hello\nworld\n")
(with [f (file/open p)] (file/read f 3))      # => @"hel"
(with [f (file/open p)] (file/read f :all))   # => @"hello\nworld\n"
(os/rm p)
(os/rm tmp)
```

`with` 的值就是區塊最後一個運算式的值，所以一行就能「打開、讀、關」。

## 你會踩的坑

⚠ 打不開的檔案不會馬上報錯

你會以為：`file/open` 一個不存在的檔，跟 `slurp` 一樣會拋錯。

其實是：它安靜地回 `nil`。包在 `with` 裡時，錯誤要到區塊結束才冒出來，
而且訊息是看不懂的 `unknown method :close invoked on nil`。

因為：`file/open` 的設計是「打不開就回 `nil`，讓你自己判斷」。
所以不確定檔案在不在，就先 `os/stat` 檢查，或讀檔改用 `slurp` 包 `try`。

⚠ Windows 上多出來的 `\r`

你會以為：用 `:w` 寫 `"x\n"`，檔案裡就是兩個 byte。

其實是：在 Windows 上會變成 `x\r\n` 三個 byte。Linux、macOS 不會。

因為：不帶 `b` 的文字模式在 Windows 會把 `\n` 自動翻成 `\r\n`。
`spit` 預設是二進位所以不翻，但 `spit` 給 `:a` 就變文字模式了，這就是 8-1 要你寫 `:ab` 的原因。
想讓檔案在每個平台都一模一樣，模式一律帶 `b`。
