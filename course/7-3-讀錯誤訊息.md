# 7-3 · 讀錯誤訊息

程式炸了，終端機印出一堆 `error:` 跟 `in ...`。這課教你把那幾行當成 Janet 在跟你講話：第一行說「為什麼」，下面幾行說「在哪裡」。學完你看到錯誤訊息會先讀再猜，而不是先猜再改。

## 這是什麼、為什麼

Janet 的錯誤分三類，**看第一行的長相就分得出來**，而且哪一類能被 `try` 接住是不一樣的。搞錯類別，你會拿 `try` 去包一個永遠包不住的錯誤，然後懷疑人生。

只有第三類（執行期錯誤）會附上一串 `in ...`，叫做 stack trace（呼叫堆疊，也就是「誰呼叫誰、一路呼叫到炸掉那格」的清單）。讀 trace 有個固定套路，下面用一個真的炸掉的檔案逐行講。

## 動手

### 先分三類

把這兩行存成 `parse.janet`（第一行少一個右括號）跑 `janet parse.janet`：

```
(print "hi"
(print "bye")
```

```
parse.janet:3:0: parse error: unexpected end of source, ( opened at line 1, column 1
```

**parse error**：括號沒收、字串沒關，檔案根本讀不完。它告訴你哪個左括號沒人配對（第 1 行第 1 格）。

```
(print "start")
(prnt "typo")
```

```
compile.janet:2:1: compile error: unknown symbol prnt
start
```

**compile error**：讀完了但這個 form（一組括號）編不成，`prnt` 這個名字不存在。注意 `start` 還是印出來了，因為 Janet 是一個 form 一個 form 編譯再執行，第 1 行早就跑完了才輪到第 2 行。

```
(def 設定 {:name "app"})
(def port (設定 :port))
(print (+ port 1))
```

```
error: could not find method :+ for nil
  in thunk [demo.janet] (tail call) on line 3, column 8
```

**runtime error**（執行期錯誤）：真的跑起來才炸，這裡是 `port` 查不到變成 `nil` 再拿去加。長相不同：開頭是 `error:`，沒有檔名與行號在前面，下面接 `in ...` 那幾行。

⚠ **前兩類 `try` 接不到**，因為它們發生在程式開始跑之前，`try` 還沒有機會執行。參數個數寫錯也是 compile error，就算包了 `try` 一樣擋在門外：

```
(defn greet [name greeting] (print greeting " " name))
(try (greet "ming") ([e] (print "接到了：" e)))
```

```
arity.janet:2:6: compile error: <function greet> expects at least 2 arguments, got 1
```

### 一個真實的 trace，逐行讀

把這段存成 `crash.janet`：

```
(defn 算平均 [nums]
  (/ (sum nums) (length nums)))

(defn 讀分數 [row]
  (def n (get row :score))
  (+ n 0))

(defn 報表 [rows]
  (def 分數們 (map 讀分數 rows))
  (print "平均：" (算平均 分數們)))

(報表 [{:score 90} {:name "ming"}])
```

跑 `janet crash.janet`，得到：

```
error: could not find method :+ for nil
  in 讀分數 [crash.janet] on line 6, column 3
  in map [boot.janet] on line 1109, column 3
  in 報表 [crash.janet] on line 9, column 18
  in thunk [crash.janet] (tail call) on line 12, column 1
```

一行一行看：

`error: could not find method :+ for nil`：為什麼炸。`+` 拿到一個 `nil`。Janet 的 `+` 是去找數值的 `:+` 方法，`nil` 沒有這個方法，所以訊息長這樣而不是「型別錯誤」。

`in 讀分數 [crash.janet] on line 6, column 3`：**炸在哪一格**。函式 `讀分數`、檔案 `crash.janet`、第 6 行第 3 格，就是 `(+ n 0)` 的左括號。這是最裡面的一層，永遠是第一行。

`in map [boot.janet] on line 1109, column 3`：誰呼叫了 `讀分數`。是內建的 `map`，它住在 `boot.janet`（Janet 核心自己的原始碼，一大半是用 Janet 寫的）。看到 `boot.janet` 通常可以跳過，那不是你的程式。

`in 報表 [crash.janet] on line 9, column 18`：誰呼叫了 `map`。第 9 行第 18 格就是 `(map 讀分數 rows)` 的左括號。

`in thunk [crash.janet] (tail call) on line 12, column 1`：`thunk` 是「檔案頂層」，也就是不在任何函式裡的那段。看到它表示追到最外面了。第 12 行就是 `(報表 ...)` 那一行。`(tail call)` 的意思等下講。

所以讀 trace 的套路：**第一行找原因，第二行找位置，往下是呼叫路徑**。順序是由內往外，跟 Python 剛好相反（Python 是最後一行最裡面）。

回頭看第 12 行的資料：第二筆 `{:name "ming"}` 沒有 `:score`，`(get row :score)` 回 `nil`，`nil` 一路走到 `+` 才炸。這就是 7-1 說的「默默帶著 nil 跑很遠才炸」。

### 常見訊息對照

這些都能用 `protect` 自己製造出來看：

```janet
(protect (+ 1 nil))     # => (false "could not find method :+ for 1 or :r+ for nil")
(protect (math/floor nil))   # => (false "bad slot #0, expected number, got nil")
(protect ([1 2] 9))     # => (false "expected integer key for tuple in range [0, 2), got 9")
(protect (:a 5))        # => (false "unknown method :a invoked on 5")
```

| 你看到的 | 實際意思 |
|---------|---------|
| `unknown symbol X` | 名字打錯，或忘了 `import`。compile error，`try` 接不到 |
| `<function f> expects at least N arguments, got M` | 參數個數不對。compile error，`try` 接不到 |
| `could not find method :+ for nil` | 算術拿到 `nil`，多半是 `get` 沒查到就直接拿去算 |
| `bad slot #0, expected number, got nil` | 內建函式的第 0 個參數要數字，你給了 `nil`。`#N` 從 0 數 |
| `expected integer key for tuple in range [0, 2), got 9` | 索引超出範圍 |
| `nil called with N arguments` | 你呼叫的東西是 `nil`，通常是名字沒定義到或模組沒載到 |
| `unknown method :close invoked on ...` | 拿 keyword 當方法用在不支援的值上，7-2 的 `with` 坑 |
| `could not find module ./x:` 加幾行路徑 | 找不到模組，那幾行就是它一一找過的地方 |
