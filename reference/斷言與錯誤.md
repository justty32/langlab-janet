# 斷言與錯誤 ・ assert／error／protect／try

[← reference 索引](README.md)

這份窮舉 Janet 內建跟「拋錯、捕捉、清理」相關的函式：`assert` `assertf` `error` `errorf` `protect` `try` `signal` `propagate` `debug`、資源清理用的 `defer` `edefer` `cancel`，以及巨集裡跟例外處理相關的 `keep-syntax` `keep-syntax!` `bad-compile` `bad-parse`。對應教學是 docs/20-錯誤處理與資源管理.md，這裡是查全部有什麼、每個實測長怎樣。全部範例皆以 `janet -e` 實測於 1.41.2。

## 拋錯

| 函式 | 簽名 | 說明 |
|---|---|---|
| `assert` | `(assert x &opt err)` | `x` 不是真值就拋錯（`err` 沒觸發不會被求值）；`x` 是真值時**回傳 x 本身** |
| `assertf` | `(assertf x fmt & args)` | `assert` 配 `string/format` 版，錯誤訊息可帶格式化參數 |
| `error` | `(error e)` | 直接拋出 `e`（任意值，不一定要字串），父層 fiber 可捕捉 |
| `errorf` | `(errorf fmt & args)` | 等於 `(error (string/format fmt ;args))` |

⚠ `assert` 成功時回傳的是**檢查的那個值本身**，不是 `true`：

```
(assert 5 "壞了")                        # => 5
```

⚠ `protect` 捕捉到的錯誤值，若是含非 ASCII（中文）位元組的字串，被 `pp`／REPL 印回來時會被跳脫成 `\xNN`，不是原字——這不是 `protect` 的問題，是 `pp`／`%q` 格式對「巢狀在結構裡的字串」一律做位元組跳脫（英文字串不受影響）：

```
(protect (assert false "壞了"))          # pp 印出 => (false "\xE5\xA3\x9E\xE4\xBA\x86")
(protect (assert false "broken"))        # pp 印出 => (false "broken")     英文不會跳脫
(print (get (protect (assert false "壞了")) 1))
                                          # => 壞了   直接 print 裸字串就正常，不會跳脫
```

## 捕捉與處理

| 函式 | 簽名 | 說明 |
|---|---|---|
| `protect` | `(protect & body)` | 跑 body，回傳 `(ok value)` 這個 tuple：成功 `ok=true`、拋錯 `ok=false` |
| `try` | `(try body catch)` | `catch` 是 `([err] ...)` 或 `([err fiber] ...)` 形式，body 出錯就跑 catch，語法比 protect 更貼近其它語言的 try/catch |
| `signal` | `(signal what x)` | 發出信號，`what` 可以是 `:ok` `:error` `:debug` `:yield` `:user0`~`:user7` `:interrupt` `:await` 之一 |
| `propagate` | `(propagate x fiber)` | 把某個 fiber 的信號原封不動轉發到目前 fiber，用來「不弄丟原始 stack trace 地重新拋錯」 |
| `debug` | `(debug &opt x)` | 拋出 debug 信號，暫停給父層檢查狀態，`resume` 帶值回來繼續跑 |
| `cancel` | `(cancel fiber err)` | 恢復一個掛起的 fiber，但強迫它立刻以 `err` 報錯，用來提前終止 |

```
(protect (+ 1 2))                        # => (true 3)
(protect (error "boom"))                 # => (false "boom")
(try (error "x") ([err] (string "caught: " err)))
                                          # => "caught: x"
```

⚠ `signal` 發出的 `:user0`~`:user7` 不會被 `protect` 當成錯誤攔下來——`protect` 只攔 `:error`；`(protect (signal :user0 "hi"))` 會直接讓整個程式當機退出（信號沒人接住）。要接 user 信號要自己在 fiber 上用對應的 mask。

`propagate` 的典型用法：外層 fiber 不要自己設 `:e`（不然錯誤會被自己吞掉、resume 只會拿到回傳值而不會真的報錯出去）：

```
(def inner (fiber/new (fn [] (error "boom")) :e))
(def outer (fiber/new (fn [] (propagate (resume inner) inner))))
(protect (resume outer))                 # => (false "boom")   原始 stack trace 保留在 outer 身上
```

```
(def fib (fiber/new (fn [] (yield 1) (yield 2)) :y))
(resume fib)                             # => 1
(cancel fib "取消了")                     # => error: 取消了   之後 (fiber/status fib) 是 :error
```

## 資源清理（跟例外流程綁在一起）

| 函式 | 簽名 | 說明 |
|---|---|---|
| `defer` | `(defer form & body)` | body 不論正常結束或拋錯（含 user0~4 信號）都會執行 `form` 做收尾 |
| `edefer` | `(edefer form & body)` | 只有 body **異常結束**才跑 `form`；正常結束就不跑，回傳 body 最後一個值 |

```
(protect (defer (print "清理了") (print "做事") (error "出錯")))
                                          # 依序印出：做事 / 清理了；回傳 (false "出錯")
                                          # （用 pp 顯示回傳值一樣會跳脫成 \xNN，跟上面同個現象）
```

## 巨集內部：保留原始語法資訊（進階）

| 函式 | 簽名 | 說明 |
|---|---|---|
| `keep-syntax` | `(keep-syntax before after)` | 把 `after` 的內容包成跟 `before` 一樣的 tuple 型別＋原始碼位置；只要有一邊不是 tuple 就原樣回傳 `after` |
| `keep-syntax!` | `(keep-syntax! before after)` | 同上，但 `after` 是 array 時會強制轉成 tuple 再套 |
| `bad-compile` | `(bad-compile msg macrof where &opt line col)` | 編譯期錯誤的預設處理函式 |
| `bad-parse` | `(bad-parse p where)` | 剖析期錯誤的預設處理函式 |

寫巨集時想讓展開後的程式碼保留原本的行號、方便報錯時定位，就用 `keep-syntax` 包一層：

```
(def before '(a b c))
(keep-syntax before @[1 2 3])            # => @[1 2 3]   after 是 array（非 tuple）就原樣不動
(keep-syntax before [1 2 3])             # => (1 2 3)    兩邊都是 tuple 才會真的套用 before 的來源資訊
(keep-syntax! before @[1 2 3])           # => (1 2 3)    array 被強制轉成 tuple
```
