# spork/getline、spork/rawterm ・ 終端互動

[← spork 索引](README.md)｜[← reference 索引](../README.md)

`spork/getline`（5 個）是可自訂的一行輸入（就是 REPL 那種能上下翻歷史、Tab 自動完成的輸入框）；
`spork/rawterm`（10 個）是更底層的終端控制：raw mode（**原始終端模式**——關掉終端機自己的
行緩衝與回顯，程式自己一個字元一個字元處理輸入，游標移動、方向鍵這些才做得到）、量測文字
在終端機上實際佔幾個字元格（monowidth，中文、emoji 這種「寬字元」佔 2 格）。

⚠ **這兩個模組的核心功能都需要真的連著一個互動終端（tty）**：這份文件是在被管線接起來的
非互動環境（`janet -e '...'`）裡測的，`(rawterm/isatty)` 直接回傳 `false`，`rawterm/begin`／
`getch` 這類要「真的接管鍵盤輸入」的函式在這種環境下不是報錯就是回傳沒意義的值——這些會
如實記錄下來，不會編造在真終端機下的輸出。想看真正效果，自己在終端機（不是這種批次執行）
開 REPL 試。

## spork/getline

| 函式 | 簽名 | 一句話 |
|---|---|---|
| `max-history` | 數字 | 歷史紀錄最多留幾筆 |
| `make-getline` | `(make-getline &opt autocomplete-context autocomplete-options doc-fetch)` | 做出一個自訂的 `getline` 函式（讀一行輸入），可換掉自動完成、文件查詢的邏輯 |
| `default-autocomplete-context` | `(default-autocomplete-context buf pos)` | 預設邏輯：從目前輸入的 buffer 與游標位置，抓出「該拿什麼字串去查自動完成」 |
| `default-autocomplete-options` | `(default-autocomplete-options prefix &)` | 預設邏輯：給一個字首，回傳目前環境裡所有符合的候選字 |
| `default-doc-fetch` | `(default-doc-fetch sym w &)` | 預設邏輯：Ctrl-G 查文件時，去哪裡撈 `sym` 的 docstring |

### 實測範例（不需要 tty 的部分）

```janet
(import spork/getline)

(def buf @"(pri")
(getline/default-autocomplete-context buf 4)
# => @[1 "pri"]     從位置 1 開始的子字串 "pri" 拿去查

(getline/default-autocomplete-options "pri")
# => @[prin prinf print printf]    目前環境裡符合字首 "pri" 的 symbol

(getline/make-getline)
# => <function getline-fn>   做出一個客製化的輸入函式，本身不需要 tty 才能「做出來」
```

⚠ `make-getline` 回傳的函式本身，跟內建的 `getline`（不在 spork 裡，是 boot.janet 內建的）
一樣要接真的互動輸入才能實際跑，這裡測不了；`default-doc-fetch` 能在非互動環境正常呼叫
（它只是查 docstring，不用 tty），會印出帶 ANSI 顏色碼的說明文字。

## spork/rawterm

| 函式 | 簽名 | 一句話 |
|---|---|---|
| `isatty` | `(isatty)` | 目前 stdin 是不是接在真終端機上 |
| `begin` | `(begin &opt on-winch)` | 進入 raw mode，回傳一個可讀取輸入的 stream |
| `end` | `(end)` | 離開 raw mode，恢復終端機正常行為 |
| `size` | `(size)` | 取得終端機目前幾列幾欄，回傳 `[rows cols]` |
| `getch` | `(getch &opt into)` | 從 stdin 讀一個 byte（非阻塞），要先 `begin` 過才能用 |
| `ctrl-z` | `(ctrl-z)` | 處理 Ctrl-Z：把目前行程掛起（suspend），讓使用者能切回 shell |
| `monowidth` | `(monowidth bytes &opt start-index end-index)` | 量一段字串在等寬字型終端機上佔幾格 |
| `rune-monowidth` | `(rune-monowidth rune)` | 量單一個 rune（碼點）佔幾格：0（零寬）、1（一般字元）或 2（中日韓文字、emoji 這類寬字元） |
| `slice-monowidth` | `(slice-monowidth bytes columns &opt start-index into)` | 從字串裡切出「剛好塞得進 `columns` 欄」的那一段 byte |
| `buffer-traverse` | `(buffer-traverse bytes index delta &opt skip-zerowidth)` | 遊標移動：從 `index` 往前/後移動 `delta` 個碼點，可選擇跳過零寬碼點 |

### 實測範例

不需要 tty 的量測函式（純計算，這幾個能正常測）：

```janet
(import spork/rawterm)

(rawterm/monowidth "hello")   # => 5     全形寬字元 2 格、一般 ASCII 1 格
(rawterm/monowidth "你好")     # => 4     兩個中文字，各佔 2 格

(rawterm/rune-monowidth (chr "a"))   # => 1
(rawterm/rune-monowidth (first "你")) # => 2

(rawterm/slice-monowidth "hello world" 5)  # => @"hello"   切出剛好 5 欄寬的部分
(rawterm/buffer-traverse "hello" 0 2)      # => 2          從 index 0 移動 2 個碼點
```

需要 tty 才有意義的部分（以下是這份文件在**非互動管線環境**下的實際輸出，不是真終端機的結果）：

```janet
(rawterm/isatty)   # => false    這個環境沒接真終端機
(rawterm/size)     # => (29840 23877)   沒接真終端機時回傳的是沒有意義的隨機值，不能當真
(rawterm/getch)    # => error: call rawterm/begin to initialize
                    #    没先 begin 就呼叫 getch 會直接報錯
```

⚠ `rawterm/size` 在非 tty 環境不會報錯，而是**安靜地回傳垃圾值**（例子中的 `29840 23877`
明顯不是任何終端機的合理列數／欄數）——這點容易誤導：程式若沒有先檢查 `isatty`，直接用
`size` 的結果去算版面，在管線或 CI 環境下會拿到看似正常實則亂數的數字。真要用終端機大小
排版，先確認 `isatty` 為真。
