# 資料格式與驗證 ・ json／schema／data／infix

[← spork 索引](README.md)｜[← reference 索引](../README.md)

json 是編解碼；schema 是「檢查一份資料的形狀對不對」；data 是結構化 diff；infix 是讓算式用中綴寫法。
四個都是純 Janet 模組。

## json

| 函式 | 簽名 | 說明 |
|---|---|---|
| `json/encode` | `(json/encode x &opt tab newline buf)` | Janet 值 → JSON 字串。`tab`／`newline` 給縮排／換行字元可排版；`buf` 給了就接到後面 |
| `json/decode` | `(json/decode json-source &opt keywords nils)` | JSON 字串 → Janet 值。`keywords` 真值時物件的 key 轉成 keyword；`nils` 真值時 JSON 的 `null` 變成 `nil`（不給就變成 `:null`） |

```janet
(import spork/json)
(json/encode {:a 1 :b [1 2 3]})            # => @"{\"b\":[1,2,3],\"a\":1}"  ⚠ 回 buffer
(json/encode {:a 1} "  " "\n")              # => @"{\n  \"a\": 1\n}"       縮排版
(json/decode "{\"a\":1,\"b\":[1,2,3]}")     # => @{"b" @[1 2 3] "a" 1}  ⚠ hash 序
(json/decode "{\"a\":1}" true)              # => @{:a 1}          （key 轉 keyword）
(json/decode "{\"a\":null}" true)           # => @{:a :null}      （null 預設變 :null）
(json/decode "{\"a\":null}" true true)      # => @{}   ⚠ 見下
```
⚠ **`nils` 給 true 時，`null` 的 key 會整個消失**：因為 Janet 的 table 不能存 `nil` 當 value
（`put` 一個 `nil` 值等於刪掉那個 key），所以 `{"a":null}` 配 `nils=true` 解出來是空 table `@{}`，
不是 `@{:a nil}`。想保留「這個 key 存在但是 null」的資訊，就不要開 `nils`，讓它留在 `:null`。

## data

| 函式 | 簽名 | 說明 |
|---|---|---|
| `data/diff` | `(diff a b)` | 遞迴比較 `a` `b`，回傳 `@[只在a的東西 只在b的東西 兩邊都有的東西]` |

```janet
(import spork/data)
(data/diff [1 2 3] [1 2 3])        # => @[nil nil @[1 2 3]]           完全相同
(data/diff [1 2 3] [1 9 3])        # => @[@[nil 2] @[nil 9] @[1 nil 3]]  逐位比較，不同處分列兩邊
(data/diff [1 2 3] [1 2 3 4])      # => @[nil @[nil nil nil 4] @[1 2 3]]  b 多出的尾巴算「只在 b」
(data/diff "kitten" "sitting")     # => @["kitten" "sitting" nil]      整串不同，當成完全不同的東西
```
最後一個例子要注意：`data/diff` 是**結構性**比較（陣列逐位置對齊、巢狀遞迴），不是字元級的最短編輯距離
（不會告訴你「k→s、去掉一個 e」這種)。兩個字串只要不完全相等，就整個列為「只在 a」／「只在 b」。

## infix

| 函式 | 簽名 | 說明 |
|---|---|---|
| `infix/$$` | `($$ & body)` | 巨集：把中綴寫法的算式（`1 + 2 * 3`）轉成正常前綴呼叫，含正常運算子優先序 |

```janet
(import spork/infix)
(infix/$$ 1 + 2)          # => 3
(infix/$$ 1 + 2 * 3)      # => 7    （* 優先序高於 +，跟數學課本一樣）
(infix/$$ (1 + 2) * 3)    # => 9    （括號照樣改變順序）
```
幾乎不會在正式程式裡用（Janet 前綴寫法才是主流慣例），列在這裡是為了完整；
比較常見的用途是寫數學公式時想貼近原始寫法。

## schema

宣告式資料驗證：给一個「形狀描述」，換回一個檢查函式。用途是設定檔／網路協定這類「格式要對，但不用到完整型別系統」的場合。
**不支援**遞迴 schema、完整錯誤報告（只回報第一個錯）、PEG 式文法遞迴、`match` 那種 unification。

| 函式 | 簽名 | 說明 |
|---|---|---|
| `schema/validator` | `(validator pattern)` | 巨集，`pattern` 不用手動 quote。回傳一個函式：驗證失敗就 `error`，成功回傳原輸入 |
| `schema/predicate` | `(predicate pattern)` | 巨集，同上但回傳布林值，不丟錯誤 |
| `schema/make-validator` | `(make-validator schema)` | `validator` 的**函式版**——`schema` 是一般引數，會被求值，所以要自己 quote |
| `schema/make-predicate` | `(make-predicate schema)` | `predicate` 的函式版，同樣要自己 quote |

⚠ **巨集版跟函式版的「要不要 quote」不一樣，混用會靜默算錯**：
`(schema/predicate (or :number :nil))` 中的 `(or :number :nil)` 因為是巨集參數，不會被求值，
原封不動當 schema 用。但 `(schema/make-predicate (or :number :nil))` 因為 `make-predicate`是普通函式，
引數會先被求值——而 `or` 剛好是 Janet 內建的特殊形式，`(or :number :nil)` 求值結果是 `:number`
（第一個真值），於是 schema 悄悄變成單純的 `:number`，不是原本想要的「數字或 nil」！
必須手動 quote：`(schema/make-predicate '(or :number :nil))`。實測對照：

```janet
(import spork/schema)
(def p (schema/predicate (or :number :nil)))              # 巨集：不用 quote
[(p 5) (p nil) (p "x")]                                    # => (true true false)  正確

(def bad ((schema/make-predicate (or :number :nil))))      # 函式：忘了 quote
[(bad 5) (bad nil) (bad "x")]                              # => (true false false) 悄悄變成只認 :number

(def ok ((schema/make-predicate '(or :number :nil))))      # 補上 quote 才對
[(ok 5) (ok nil) (ok "x")]                                 # => (true true false)  正確
```

**schema 語法**（`pattern` 可以嵌套）：

| 寫法 | 意思 |
|---|---|
| `:keyword`（如 `:number` `:string`） | 檢查 `(type x)` 是不是這個型別 |
| `(any)` | 什麼都算過 |
| `(enum v1 v2 ...)` | 值等於其中一個 |
| `(or s1 s2 ...)` | 任一 schema 符合即可 |
| `(and s1 s2 ...)` | 全部都要符合 |
| `(values s)` | 資料結構裡**每個 value** 都符合 `s` |
| `(keys s)` | 每個 **key** 都符合 `s` |
| `(props k1 v1 k2 v2 ...)` | 逐一檢查 `(get x k1)` 符合 `v1`……——**要做「struct 每個欄位分別驗證」必須用這個**，不是直接寫裸 struct |
| `(length n)` / `(length min max)` | 長度剛好 n／落在區間 |
| `(peg pat)` | 用 PEG 比對（見文字比對.md） |
| `(not s)` | 不符合 `s` |
| `(pred f)` | 自訂謂詞函式 |
| 其他（字面值） | 直接用 `=` 比較 |

⚠ **裸 struct/table 當 schema 寫（如 `{:name :string}`）不會逐欄位檢查，而是整包拿去跟輸入值做 `=` 比較**，
幾乎必然失敗（因為值不可能剛好跟 schema 描述本身相等）。要驗證「有這些欄位、各自符合某型別」一定要用 `(props ...)`。

```janet
(import spork/schema)
(def p (schema/predicate (props :name :string :age :number)))
(p {:name "a" :age 1})     # => true
(p {:name "a" :age "x"})   # => false

(def p2 (schema/predicate (peg (some (range "09")))))
(p2 "123")   # => true
(p2 "abc")   # => false

((schema/predicate (not :number)) "x")        # => true
((schema/predicate (pred even?)) 4)           # => true
((schema/predicate (length 2 4)) "abc")       # => true
((schema/predicate (values :number)) [1 "x" 3])  # => false   （有一個不是數字）
```
