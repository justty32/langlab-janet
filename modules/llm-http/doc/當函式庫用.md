# 當函式庫用

[← 回 llm-http README](../README.md)


**怎麼 import（路徑規則、`:as`、裝起來用裸名字）→ 見 [`../README.md`](../../README.md#怎麼-import-這些模組)。**
下面假設你的檔案在根目錄下一層（`test/`、`bin/` 那種）：

```janet
(import ../modules/llm-http/init :as llm)

(def cfg (llm/endpoint "local"))                    # 或 "deepseek"／"claude"／"openrouter"
(print (llm/ask cfg "台灣最高的山是哪座？"))          # 一行式問答
(print (llm/ask cfg "1+1？" "只回數字，不要解釋"))    # 第二個參數是 system 訊息
(print (llm/ask cfg "這是什麼？" nil ["a.png"]))     # 第三個參數是圖檔陣列
(print (llm/ask cfg "1+1？" nil nil :temperature 0)) # 之後是具名參數，原樣轉給 chat
```

`ask` 的簽名是 `(ask cfg prompt &opt system images &named …)`——system 跟 images 都可省略，
只要 images 不要 system 時中間給 `nil`。

⚠ **`import` 這個模組的副作用**：會自動探測一次你的 endpoint 設定檔（見上面 ③）。
沒有設定檔是正常狀態，不會有任何輸出。只 `import ./registry` 的話不會觸發自動載入
——那是刻意的，讓純函式那層保持乾淨。

### tool loop

`with-tools` 把「模型要工具 → 本地執行 → 結果送回 → 模型作答」這個循環包起來，
自己轉圈直到模型不再要求工具，並有 `:max-rounds` 上限防無限迴圈。

```janet
(def tools
  [(llm/tool-spec "get_weather" "查詢城市目前天氣"
                  {:type "object"
                   :properties {:city {:type "string"}}
                   :required ["city"]})])

# handlers 是「工具名 → Janet 函式」；函式收一張解好的參數 table，
# 回字串（或任何東西，非字串會被 encode 成 JSON）
(def handlers
  {"get_weather" (fn [args] {:city (args :city) :temp_c 31 :cond "晴"})})

(def out (llm/with-tools cfg
                         @[@{:role "user" :content "台北天氣？用工具查"}]
                         tools handlers
                         :system "你只能用繁體中文回答"   # 可省略，見下
                         :max-rounds 8
                         :temperature 0.2                # 參數原樣轉給每一輪的 chat
                         :trace (fn [name args result] (eprintf "→ %s" name))))
(print (out :text))        # 最終答案；撞到上限時是 nil，(out :exhausted) 為 true
(out :messages)            # 完整歷史，含 assistant 的 tool_calls 與 role:"tool" 的結果
```

handler 自己丟例外不會炸掉整條 loop——錯誤會被**當成工具結果送回模型**，讓它有機會改參數重試。
完整示範（自訂工具、多工具、handler 丟例外）→
[`../../examples/llm-http/04-tools.janet`](../../../examples/llm-http/04-tools.janet)。

#### tool loop 的 system 訊息

`with-tools` 吃的是**完整的 `messages` 陣列**（tool loop 本來就要你掌控整段歷史），
所以 system 有兩種給法，擇一即可：

```janet
# ① 用 :system 具名參數 —— 跟 ask 對齊，省得自己組 role/content
(llm/with-tools cfg @[@{:role "user" :content "…"}] tools handlers
                :system "你只能用繁體中文回答")

# ② 自己放進 messages 第一則 —— 想更精細控制歷史時用這個
(llm/with-tools cfg @[@{:role "system" :content "你只能用繁體中文回答"}
                      @{:role "user"   :content "…"}]
                tools handlers)
```

⚠ **`:system` 只在 `messages` 第一則還不是 system 時才會插入**——已經自己放了就會被忽略，
避免一次送兩則 system 讓模型無所適從。要換掉原本那則就直接改 `messages`，別靠 `:system` 覆蓋。

CLI 的 `-s` 走的是 ②（先組進 `messages` 再交給 loop），所以 `-s` 跟 `--tools` 可以一起用：

```sh
./build/llm-http --tools -s "你只能用日文回答，一句話。" local "現在幾點？用工具查。"
# → 工具 now()
# ← 2026-08-03T22:00:13Z
# 現在時刻は協定世界時で2026年8月3日 22時0分13秒です。
```

### 公開 API 一覽

| 分類 | 函式／值 |
|------|----------|
| 預設值 | `default-base` `default-proxy-key` `chat-path` `base-url` `chat-url` `proxy-key` |
| endpoint 資料 | `builtin-specs`（不可變的內建四筆）`specs`（**活的** registry） |
| registry | `endpoint` `endpoint-names` `builtin-names` `define-endpoint` `undefine-endpoint!` `reset-endpoints!` `endpoint-source` `builtin-endpoint?` `normalize-spec` `env-ready?` `spec-keys` |
| 設定檔 | `load-endpoints!` `autoload-endpoints!` `config-candidates` `parse-endpoints` `loaded-files` |
| 傳輸 | `post-chat` `headers-for` |
| 對話 | `chat` `ask` `build-payload` `reply-text` `reply-message` `param-aliases` |
| 圖像 | `user-message` `image-part` `text-part` `data-uri` `mime-for-path` `mime-by-ext` |
| tool loop | `with-tools` `tool-spec` `demo-tools` `demo-handlers` |

**相容性**：舊有的公開 API 全部照舊——`endpoint`（吃名字字串那條）、`endpoint-names`、
`specs`、`env-ready?`、`base-url`、`chat-url`、`proxy-key`、`chat`、`ask`、`post-chat`、
`reply-text`、`reply-message`、`tool-spec`、`with-tools`、`demo-tools`、`demo-handlers`、
`user-message`，簽名與行為都沒變。

⚠ **`specs` 唯一的語意變化**：它從不可變的 `struct` 變成**活的 `table`**（registry 本體），
會長出你自訂的 endpoint。讀法完全不變（`(get specs "local")`、`(keys specs)`），
只是現在也看得到自訂的那些。**只想要內建那四筆**（跟舊版的 `specs` 完全等價的東西）
請改讀 `builtin-specs`——那份仍然是不可變的 struct。
